# 工作区滚动与顶栏整理

## 问题与原因

“查看详情”使用 `scrollIntoView`，浏览器会尝试滚动所有祖先容器，而不只是聊天记录。桌面右侧面板的顶部外边距与已有的 100% 高度叠加，又使工作区产生了额外溢出。

真实任务在 1912 × 948 窗口中，点击前后工作区内部滚动从 0 变为 66px；聊天区、播放器因此一起向上移动，底部出现空白。

## 本次修改

- 定位卡片只滚动聊天记录。卡片已完整可见时不移动；保留高亮和键盘焦点，并尊重减少动画设置。
- 清除右侧面板多余顶部外边距；桌面工作区外壳禁止程序滚动，聊天、素材列表等内部滚动不受影响。
- 桌面已打开任务的项目入口合并到视频标题栏，当前任务待办入口移到左侧导航下方。保留原按钮及事件，不复制按钮。
- 回收原 48px 顶栏和 10px 底部预留，工作区填满可用高度。源片与项目同名时不重复显示文件名；长标题保留悬停提示。
- 小于 1280px 的窗口恢复原顶栏导航；桌面新建任务页隐藏空项目顶栏并回收上下占位，任务切换仍可从左侧“任务”进入。切回已有任务后恢复视频标题栏的项目入口及左侧待办。首页不残留当前任务铃铛。二次编辑仍隔离背后的工作区入口。
- 按现有界面改造技能采用局部调整，未重写布局系统或更改任务处理逻辑。

## 验证

- 聊天卡片、工作区布局、样式重复检查：43 项通过。
- 工作区交互回归：75 项通过。
- 前端静态检查通过；重复样式告警为 0。
- 真实任务连续点击三次查看详情：工作区始终为 top=0、bottom=948、scrollTop=0，右侧面板未溢出。
- 390、1024、1280、1440、1912px 宽度检查，无页面横向溢出；迁移后任务列表和待办弹窗仍可打开。
- 检查深浅色按钮、收起两侧面板、打开已有二次编辑及返回。真实任务验证拦截非只读 API，没有生成视频或改写任务。

刷新网页即可生效，不需要重启后端。

## 补充：新建任务页取消桌面空顶栏

桌面新建任务不再保留“新任务”下拉和待办铃铛，隐藏的工具栏同时禁止键盘聚焦。仅移除空项目的顶部占位，不修改上传或任务创建逻辑；窄屏保留原导航。

验证：34 项相关测试通过，前端静态检查通过，重复样式告警为 0。实际 1912 × 948 页面工作区 top=0、bottom=948，scrollHeight 与 clientHeight 均为 948，上传入口完整可见；进入已有任务后项目入口及待办正常恢复。实际页面验证未触发写入请求，无脚本异常。

## 补充：让“查看详情”真正打开详情

顶部操作条的“查看详情”现已直接打开已有方案面板，并始终进入“方案”页；不再仅调用卡片定位。对应当前卡片不再重复显示“方案详情”按钮；没有顶部入口的失败、执行中及历史状态仍保留卡片入口。通用卡片定位继续保留，只用于确实需要定位聊天内容的操作。

关闭面板会将焦点交还触发按钮，不滚动工作区。另修复旧样式将窄屏详情面板宽度压至 0 的问题：小于 1280px 时使用四边留 8px 的独立面板。

补充验证：53 项相关测试通过，静态检查通过；真实任务在 1912、1024、390px 窗口均可打开、切换方案/活动、关闭并重新打开详情。浏览器无脚本异常，查看过程未发起写入请求。
