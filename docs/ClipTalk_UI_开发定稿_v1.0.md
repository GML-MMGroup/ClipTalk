# ClipTalk UI 重设计开发定稿

**版本：v1.0 · 设计基线 A**  
**日期：2026-09-05**  
**适用对象：前端开发、交互设计、测试、编码助手**  
**交付性质：界面与交互开发规格，不是宣传图，不是后端重构方案**

> 最终方向：以用户选定的第一版原型作为桌面端工作台的视觉与结构基准——暖米色外背景、单一悬浮式墨绿炭色工作台、左侧剪辑助理、中央视频与时间线、右侧视觉化结果卡片。除非会伪造后端能力、破坏数据安全或绕过必要确认，布局比例、视觉层级、组件尺度和空间关系均应优先贴近原型；不能只复用配色后继续沿用旧后台布局。

## 阅读与执行规则

本文件是开发主文档；配套 `tokens.css` 是视觉变量与基础布局样式，`ui-contracts.ts` 是前端归一化状态契约，`验收清单.md` 是可执行的验收用例。配套文件是实施起点，不等于已经接入现有项目或通过浏览器测试。

“必须”表示本次改版的验收要求；“默认”表示首次进入状态，允许按规则调整；“仅在能力存在时”表示必须由现有代码或接口能力确认后显示，不得用静态假按钮代替。源文件没有提供的服务端枚举、容量上限、真实接口、保存机制，不在本文中伪造。

**来源与边界。** [S1] 用户上传的《ClipTalk 现有界面完整盘点》，文件名 `ui设计`，生成日期 2026-09-05，共 33 节；[S2] 用户原始参考图 `ui.png`；[S3] 用户选定的第一版原型 `a_clean_modern_dark_and_beige_ui_mockup_of_a_vide.png`。本文引用现有功能时以 `[S1 §编号]` 定位。尺寸、颜色、布局和状态契约是本次设计明确的新规格，不是声称从截图精确测量得到的数值。未取得仓库源码，因此实际事件绑定、接口字段、资源路径仍需开发在接入时核实；本文不宣称这些已完成源码验证。

**冲突优先级。** 数据安全与真实业务能力 > 原型的视觉结构与层级 > 本文交互规则 > 旧界面兼容。原型不能授权伪造后端能力，也不能取消确认、校对和版本保护；除此之外，不能用“保留旧 DOM/旧样式”为理由牺牲原型的三栏比例、视觉焦点和卡片化结果表达。

### 视觉还原验收基准

桌面端以 `[S3]` 的完整工作台画面作为第一验收对象，而不是只抽取色板。必须同时满足：

1. 页面外部能清楚看到暖米色画布，应用主体是一个带统一圆角和阴影的完整深色工作台。
2. 左栏约占工作台宽度的 19%—22%，必须包含清晰品牌、新建任务主按钮、Agent 身份、简短快捷入口和底部输入区，不能退化成 60px 图标轨或日志列表。
3. 中栏是绝对视觉中心，视频预览明显大于文字信息；播放控制、时间线和素材画面形成连续编辑器，而不是互相割裂的状态卡片。
4. 右栏约占 22%—25%，使用带缩略图或清晰视觉分组的结果卡片表达审核、素材和版本；不允许默认呈现为密集小字表格。
5. 第一屏避免大面积无意义空白、重复阶段条、厚分割线和多层卡片嵌套。状态说明应短，详细日志进入二级页面。
6. 允许将原型中的虚构能力替换成真实能力，但替换后必须保持相同的视觉重量。例如 Music 轨不存在时，应由真实字幕、证据或片段轨补足结构，不能直接留下空区。
7. 桌面基准截图使用 `1536×960`；同时验证 `1280×800` 和 `390×844`，不得出现裁切、遮挡或通过移动 DOM 造成的闪烁。

## 01. 范围与不可变约束

### 1.1 本次要交付的结果

改造现有 ClipTalk Web 工作台，使上传、规划、审核、成片、精剪、导出形成同一套界面语言；保留现有流程和能力，只重组入口、容器、层级与状态表达。默认沿用当前工程技术栈，不因为原型图而迁移框架、重写 Agent 或替换视频引擎。[S1 §1、§32]

| 必须保留 | 本次呈现方式 | 不允许的替代 |
|---|---|---|
| 上传、任务列表、当前任务、成片库、设置 | 集成在左侧导航和独立管理页面 | 只留下一个“New Chat”按钮 |
| 自然语言输入与四种快速模式 | 输入框常驻；快速模式首次展开、后续折叠 | 把快速模式放到看不见的设置页 |
| Agent 自动/手动 Skill、执行方式、计划确认 | 输入设置菜单＋轻量计划摘要＋详情抽屉 | 输入后不经计划确认直接分析或渲染 |
| 源片、成片版本、播放与审核 | 中央统一播放器，显式区分时间坐标 | 点击候选后悄悄改变成片版本 |
| 高光、内容、人物、说话人审核 | 右侧按当前模式切换，不同时堆满 | 四块营销卡常驻，代替真实审核 |
| 主时间线、封面片头、二次精剪 | 同一视觉语言，保留各自业务语义 | 把源片分析轨伪装成可任意剪改的成片轨 |
| 字幕校对、下载、发布包、版本保存 | 明确的专门界面与导出流程 | 用“导出”一个按钮跳过原有确认 |
| 模型配置、服务状态、Skills / Plugins | 管理页面与能力抽屉 | 删除高级功能来换取简洁 |

### 1.2 明确不在范围内

不新增账号、会员、支付、云协作、团队空间、第三方社交发布、独立配乐库、自动音乐生成或新的推荐算法。第一版图中的 `BETA`、用户头像、系统三色窗口按钮、悬浮机器人、手写标语，以及默认 Music 轨道都不是功能需求。已有文本图层和字幕能力继续保留；它们不构成新增配乐能力。[S1 §23]

### 1.3 关键数据规则

上传或选择素材不等于授权分析；生成计划与执行计划分离。AI 修改先展示提案，再确认应用。高清导出产生新版本，不覆盖样片或已有版本。选择封面不等于重新编码视频。人物与声音使用项目内编号或用户主动命名，不能自动推断真实身份或敏感属性。[S1 §7、§9、§18—§21、§23—§24]

## 02. 第一版原型的取舍定稿

| 原型元素 | 定稿处理 | 开发说明 |
|---|---|---|
| 暖米色页面外背景 | 保留 | 仅作为工作台外框；不铺到时间线和播放器内部 |
| 墨绿炭色深色工作台 | 保留 | 统一所有嵌入面板的表面层级，清理残留纯白控件 |
| 鼠尾草绿按钮 | 保留 | 用于当前主动作、发送和选中提示，不变成荧光渐变 |
| 右侧柔和彩色卡 | 保留分类气质、压缩面积 | 彩色主要用于模式入口及结果分组头；真实长列表仍使用深色底 |
| 左对话、中预览与时间线、右侧结果 | 保留 | 右侧由当前上下文驱动，不是永远展示四种功能广告 |
| 大品牌字标 | 缩小 | 左上使用现有 Logo 资源，保持原图标，不从生成图重新描摹 |
| “New Chat” | 改为“新建任务” | 复用现有新建任务逻辑，不产生第二套会话系统 |
| 五个快捷入口 | 恢复为四个真实快速模式 | 高光剪辑、内容探索、按人物剪辑、按说话人剪辑 |
| 大机器人与外置标语 | 工作台移除 | 品牌头像最多在助理头部和空态出现，不遮挡工作区域 |
| 外置斜切、悬浮右栏 | 改为规整停靠栏 | 窗口内统一网格，不使用负 margin 制造溢出 |
| 底部重复素材胶片带 | 不默认常驻 | 素材集中在右栏；精剪素材库按需要打开 |
| 音乐轨、默认背景音乐 | 不新增 | 没有已确认能力就不展示可操作音乐轨 |
| 视频中的手写口号 | 不叠加 | 播放器只展示实际媒体、真实字幕和已确认文本图层 |

**整体质感约束。** 不做霓虹灯、玻璃拟态、大面积渐变、发光描边、彩虹标签或每条消息一个厚卡片。柔和来自色温、间距、表面层级与字体，不来自装饰堆叠。

## 03. 信息架构与区域职责

### 3.1 页面结构

```text
ClipTalk
├─ 首页 / 新建任务
│  └─ 选择素材 → 本地预览 → 任务草稿
├─ 工作台
│  ├─ 左：导航、素材摘要、助理对话、计划摘要、输入
│  ├─ 中：任务工具栏、媒体预览、源片/成片时间线
│  └─ 右：审核 / 素材 / 版本，附当前选中对象详情
├─ 精剪模式（复用现有 secondaryEditor）
│  ├─ 素材库
│  ├─ 预览 + 成片时间线
│  └─ 片段 / 字幕 / AI 修改 / 导出属性
├─ 成片库
└─ 设置
   ├─ 视觉分析 / 剪辑规划 / Agent 模型
   ├─ 运行环境与服务状态
   └─ Skills / Plugins
```

任务列表仍是快速切换抽屉；计划活动仍是可展开详情；字幕校对仍是专门审核界面。重组容器不取消原有深层入口。[S1 §4—§5、§9、§23—§28]

### 3.2 唯一主责

| 区域 | 负责 | 不负责 |
|---|---|---|
| 左侧助理 | 描述需求、补充信息、确认计划、查看简短进展 | 承载全部候选、所有版本、大量证据详情 |
| 中央预览 | 看当前媒体、定位、比较源片与当前版本 | 显示模型技术日志、营销文案 |
| 中央时间线 | 表达时间、选区、事件分布及当前可编辑对象 | 充当所有模式的表单集合 |
| 右侧审核 | 选片段、校正对象、查看证据、生成结果 | 复制对话中整份计划、长期堆四种模式广告 |
| 右侧素材 | 搜索候选、筛选、预览与加入 | 第二套独立选中状态 |
| 右侧版本 | 选择、比较信息、精剪、下载和保留版本 | 直接覆盖旧版本 |

### 3.3 工作模式与右栏

右栏一级标签固定为“审核 / 素材 / 版本”。“审核”的内部内容随当前任务切换：高光事件、内容匹配、人物、说话人。当前任务允许保留多次结果，但一次只激活一个结果集。对象详情进入右栏内的二级页面，顶部有“返回审核”和对象名称；不再在工作台上叠加第二条常驻检查器。

“素材”保留候选抽屉能力：点击“展开全部”可以打开更宽的候选抽屉，但两处必须共享查询、选择及预览上下文。“版本”成为版本列表唯一主位置；播放器上方只保留紧凑版本选择器。[S1 §12—§18]

## 04. 桌面布局、尺寸与响应式

### 4.1 布局基线

以 **1440×900 CSS 像素** 为常规验收基线，另验收 1920×1080、1600×1000、1366×768、1024×768、768×1024 和 390×844。截图物理像素不等于 CSS 像素。

工作台采用三列结构，左侧不再额外叠加 72px 独立导航轨：把现有 `appSidebar` 的功能集成进左侧主栏，但保留相关 ID 和事件绑定。中央与右侧共用 56px 任务工具栏。左右栏宽度可拖拽，默认按下表设置。[S1 §3—§4、§30]

| 视口宽度 | 外边距 | 左栏默认 | 右栏默认 | 中央计算结果示例 |
|---|---:|---:|---:|---|
| ≥1800px | 16px | 326px | 374px | 1920px 时中央约 1140px |
| 1600—1799px | 16px | 316px | 356px | 1600px 时中央约 850px |
| 1440—1599px | 16px | 308px | 340px | 1536px 时中央约 828px |
| 1121—1439px | 8px | 282px | 314px | 1280px 时中央约 644px |
| 768—1120px | 8px | 改为视图切换 | 改为视图切换 | 不硬塞三列 |
| <768px | 0 | 窄屏任务视图 | 窄屏任务视图 | 保留核心流程，限制复杂精剪 |

中央宽度 = 视口 − 两侧外边距 − 左栏 − 右栏 − 两条 8px 分隔区。表中中央宽度包含中央自身内边距。中央常规可用最小宽度设为 640px；不能靠给面板固定宽度让页面横向溢出。

**打开右栏规则。** 1121px 以上保持三栏并允许拖动左栏调整对话与视频的占比；1120px 以下切换为“对话 / 预览 / 审核”三个单视图，避免压缩中央视频或产生横向滚动。切换只改变可见区域，不改变对话、审核选择或版本状态。

### 4.2 高度分配

外层高度使用 `100dvh`，工作台内部使用 `min-height: 0` 和区域独立滚动。禁止整个工作台随消息增长向下推走输入框或时间线。

| 部位 | 默认尺寸 | 规则 |
|---|---:|---|
| 工作台圆角 | 18px | 窄屏降为 0；内部面板不逐层复制大圆角 |
| 全局任务工具栏 | 56px | 项目名、任务状态、上下文主动作 |
| 左侧品牌行 | 56px | Logo、品牌、新建任务入口 |
| 左侧导航行 | 40px | 工作区、任务、成片；设置与服务放底部 |
| 素材摘要 | 64px | 单行文件名、时长；详情展开，不堆技术参数 |
| 左侧计划摘要 | 40—64px | 仅有活动计划时出现，最多两行 |
| 对话滚动区 | 剩余高度 | 独立滚动；新消息不强抢用户阅读位置 |
| 输入区 | 最小 124px，最大 220px | 文本 2—6 行后内部滚动 |
| 左侧底部工具行 | 36px | 服务、设置、快捷键入口 |
| 右栏标签行 | 40px | 审核 / 素材 / 版本 |
| 右栏底部动作区 | 64—88px | 固定底部，摘要＋本区域一个主动作 |
| 中央时间线 | 常规 240px | 可拖至 180—480px，同时保留预览最小高度 |

视口高度小于 800px 时，时间线默认 180px；高度达到 1000px 时默认 280px。预览区采用剩余空间，不强制把视频画面填满整个区域。高度不足时轨道区内部滚动，不能把播放控制隐藏。

### 4.3 分隔器与滚动

分隔区布局宽 8px，鼠标有效命中区不少于 12px；悬停才出现轻量拖拽提示。左右栏建议范围 248—420px、280—420px，仍须满足中央最小宽度。双击恢复当前断点默认值，键盘方向键每次调整 8px。拖拽时不选择页面文字；`pointercancel`、失焦和释放到窗口外均结束拖拽。

对话、审核列表、时间线分别拥有独立滚动容器；滚动边界不串到背景。悬浮菜单必须逃离局部 `overflow: hidden` 的裁剪，使用既有 portal 或等效统一覆盖层。

### 4.4 竖屏与小屏

竖屏视频始终 `object-fit: contain`；黑边属于视频舞台背景，不能用裁切换取铺满。保留现有横向/竖向布局切换和竖屏宽度调节入口，集中到播放器“显示”菜单。窄屏的“对话 / 预览 / 审核”是工作区视图切换，不创建三份状态。

小于 1024px 时仍可上传、输入、确认计划、预览、选结果与下载；复杂多轨精剪入口显示“请在宽屏窗口中精剪”，同时保留返回当前任务的路径。字幕文本校对仍可进行，拖动字幕位置可改用预设位置按钮。不得仅弹一句“不支持手机”后封死已有任务。

在标准工作台中，除真实视频和缩略图外，浅彩色区域原则上不超过可见界面的 12%；这是实施面积控制目标，不是截图测量结论。不要把每个结果都铺成不同颜色。

### 5.2 字体与间距

UI 使用现有可用字体栈：`Inter, Noto Sans SC, PingFang SC, Microsoft YaHei, sans-serif`。不为开发交付额外分发字体文件。数字、时间码、版本技术标识使用等宽字体或 `tabular-nums`；正文不使用衬线字体、手写字体和花体。品牌沿用现有图标与字标资源。[S1 §2]

| 层级 | 字号 / 行高 | 字重 | 场景 |
|---|---|---:|---|
| 页面标题 | 24 / 32px | 600 | 首页、成片库、设置 |
| 工作区标题 | 18 / 26px | 600 | 当前页大分区 |
| 面板标题 | 15 / 22px | 600 | 剪辑助理、当前审核 |
| 正文与主要控件 | 14 / 22px | 400 / 500 | 对话、按钮、结果标题 |
| 元信息 | 12 / 18px | 400 | 时间、来源、非主任务说明 |
| 时间线标尺 | 11 / 16px | 500 | 仅紧凑标尺，不用于操作名称 |

使用 4px 间距基准：4、8、12、16、20、24、32。面板内边距一般 16px，密集列表 12px。圆角：小标签 4px、按钮和输入 8px、卡片 10px、浮层 12px、工作台 18px。胶囊只用于播放主按钮或真正的紧凑状态，不把每个标签都做成胶囊。

### 5.3 边框、图标与阴影

相邻工作区域使用底色差或一条分隔线，不做“双边框＋阴影”。阴影只用于外壳与浮层；卡片靠表面区分。图标使用项目现有统一 SVG 图标集，16px/20px 两档，线宽一致。不能把 emoji 当操作图标；机器人是品牌头像，不是每行状态的装饰符号。

输入框与可操作边界应达到本项目设定的可辨识要求；正文的目标对比度不低于 4.5:1，重要非文字控件的目标对比度不低于 3:1。细微的布局分隔线不承担识别控件的唯一职责。颜色需要分别在实际深底和浅卡上测试，不能只检查 token 表。

## 06. 基础组件规格

### 6.1 按钮与主动作

| 类型 | 默认规格 | 规则 |
|---|---|---|
| 主按钮 | 高 36px、左右 14px、浅绿底深字 | 同一动作区域最多一个；文案说明结果 |
| 次按钮 | 高 36px、深色底、必要边框 | 修改规划、返回审核、查看详情 |
| 文字按钮 | 高 32px、无常驻底 | 低频导航，不承担唯一关键入口 |
| 图标按钮 | 可见 32×32px | 必须有可访问名称和悬停提示 |
| 紧凑工具 | 可见 28—32px | 仅时间线；触摸命中区至少 44×44px |
| 危险按钮 | 危险色文字或浅危险底深字 | 不复用主绿色样式 |

状态至少包含：默认、悬停、按下、键盘焦点、禁用、提交中、失败可重试。提交中按钮保持原宽，防重复提交；页面切换不能使同一请求被再次发送。禁用要有就地原因，不只变淡。

“同一区域一个主动作”不是让全站只有一颗绿按钮：输入区发送可以常驻，但生成动作不能同时在左栏、右栏和顶部出现三个同权重副本。

### 6.2 列表、卡片与标签

审核项优先采用有缩略图的列表行，最小行高 88px，常规缩略图 104×58px；288px 右栏内可降到 88×50px。标题最多两行，时间范围一行，证据概述一行，其余进入详情。标题完整内容可通过展开或详情阅读，不能只提供鼠标悬停气泡。

卡片点击预览与复选框选择分离。勾选不自动播放；点击标题或缩略图才定位。当前预览用播放图标/侧边标记表示，当前已选用复选框与边框表示，不能只用一种绿色让用户猜含义。

状态标签只在会影响操作时显示，例如“需复核”“生成中”“已保留”；默认不在每行都重复“AI”“智能”“推荐”。分数仅当后端确实提供且定义明确时展示，不把相似度伪装成概率，也不在不同任务之间比较不可比分数。

### 6.3 表单与菜单

普通输入高 36px；textarea 自动增高。字段必须有可见标签，提示文本不能代替标签。校验在失焦与提交时执行；输入中不频繁打断。时间、时长、数量都有单位，错误显示在字段下方并关联到输入。

下拉菜单向可容纳方向展开，最大高度为视口扣除上下 16px；支持键盘、Esc 和点击外部关闭。菜单不得被时间线或视频容器裁切。嵌入的浏览器原生控件应设置适配深色的 `color-scheme`，浅色分类卡上的输入按实际表面单独覆盖。

### 6.4 动效

悬停 120ms、面板与抽屉 180ms、轻量状态切换不超过 240ms。视频播放、拖拽、波形与播放头不加缓动，避免延迟感。尊重减少动态效果设置；关闭闪烁、呼吸灯、循环发光及大面积骨架闪光。真实进度发生变化才更新进度条，不伪造“努力工作”的动画。

## 07. 首页、上传与任务草稿

### 7.1 首页

首页与工作台共用暖米色外底和深色内容壳。主标题“开始一个剪辑任务”；一个主入口“选择视频”，下方展示最近进行中/待确认任务。统计数据缩成低权重文字，不占据三块大 dashboard 卡。任务失败和读取失败要区分：列表读取失败显示“最近任务暂时无法加载 / 重新加载”，不能伪装成没有任务。[S1 §6]

### 7.2 上传流程

```text
选择文件 → 本地校验 → 本地预览 → 上传/建立素材工作区
→ 任务草稿（等待用户输入或选择模式）→ 生成计划 → 用户确认 → 执行
```

首次选择后，中央立即展示可用的本地视频预览；左侧进入任务草稿，右侧展示轻量“开始方式”或保持未产生结果的空态。上传状态与分析状态分开：上传完成只能显示“素材已就绪”，不能显示“分析完成”。[S1 §7—§8]

| 项目 | 实施要求 |
|---|---|
| 文件格式 | 保留 MP4 / MOV / MKV / WebM / M4V / AVI；同时检查真实媒体探测结果，不能仅信扩展名 |
| 文件容量 | 从现有服务限制读取并展示；未知时不编造 2GB 等上限 |
| 浏览器无法解码 | 说明“素材可用，但当前浏览器无法直接预览”；仅在已有代理预览能力存在时给生成/打开入口，不能擅自启动新转码任务 |
| 上传进度 | 有字节总量才显示百分比；否则显示“上传中” |
| 拖放 | `dragenter/leave` 用计数避免边框闪烁；只对文件拖放高亮 |
| 更换视频 | 未执行草稿可替换；已有分析/成片时先说明影响并走现有新任务或替换流程，保留旧任务与成片 |
| 添加素材 | 仅在现有添加源视频逻辑支持时启用；不能把单素材流程改成伪多素材工程 |
| 本地资源 | 切换文件和销毁预览时释放 Object URL；同一文件反复选择仍可触发 |
| 中断恢复 | 仅在现有上传协议支持时提供“继续上传”，否则明确“重新上传” |

### 7.3 草稿与快速模式

左侧首次显示“想把这段视频剪成什么？”与四个高度 52—64px 的模式入口，每个一个图标、一行名称、一行简短说明。分类浅色只用于模式图标/小标题区域，避免四张大亮卡挤走输入框。

| 模式 | 快捷填充/设置 | 不得隐含执行 |
|---|---|---|
| 高光剪辑 | 目标时长、版本数、素材范围 | 不因原型写 60s 就默认强制 60 秒 |
| 内容探索 | 引导输入动作、场景、对白、屏幕文字等描述 | 不默认启动所有模型进行全量分析 |
| 按人物剪辑 | 识别后确认人物与匹配方式 | 不能凭输入名字自动认定画面真实身份 |
| 按说话人剪辑 | 预计人数自动/1—12、试听确认 | 不能把“声音”和“出镜人物”当同一对象 |

直接输入与模式选择并列有效。点击模式只填入上下文、展开相关必要设置，不立即发送。模式已选但输入不完整时显示具体缺失项。Skill 默认“自动选择”；手动指定后明显显示“本次：某 Skill”，不覆盖用户已经输入的要求。

素材范围保留“全片、开头、前半段、中段、后半段、结尾、自定义”。这些范围的实际时间以现有解析规则为准，计划中展示最终入点/出点；没有解析结果时不能在 UI 里随意规定“开头=10%”。自定义时间满足 `0 ≤ 入点 < 出点 ≤ 素材时长`。

## 08. 左侧剪辑助理与输入

### 8.1 固定结构

自上而下：品牌行、导航行、当前素材摘要、活动计划摘要、对话、输入、服务与设置。阶段进度只保留一份简短状态，不同时保留顶部四阶段、聊天四阶段和右侧四阶段。[S1 §8、§29]

对话采用开放式消息：助理正文不套厚边框卡；用户消息可使用略提亮底。品牌头像只出现在助理轮次开头，连续活动合并。工具调用明细默认收进“活动”，不把每个工具都当新的对话气泡。

### 8.2 输入工具条

常驻：Agent/Skill 菜单、快速模式、素材添加/更换、引用上下文、发送。优化指令收进输入区更多菜单并保留能力。图标必须使用真实说明，例如“引用当前画面”，不能只放含义模糊的 `⌘`。[S1 §8]

引用上下文在输入框上方显示可移除的小行：“源片 · 00:18.200”或“V002 · 片段 3”；保存的是任务 ID、素材/版本 ID、坐标系与时间范围，不只是显示文本。改变预览不会偷偷修改已引用对象。

Enter 发送、Shift+Enter 换行；中文输入法组词期间 Enter 只确认候选字。发送后保留可追溯的用户消息，网络失败提供“重试发送”；重试使用原请求关联，不生成重复业务动作。输入为空、纯空白或缺少必需素材时禁用发送并说明原因。

### 8.3 滚动与阶段消息

用户在底部时跟随新消息；用户向上阅读时保持位置，显示“有新消息”入口。流式更新同一消息，不新增数十张卡。切换任务时将旧历史折叠为“此前任务对话”，不得混入当前任务的选择状态。

典型助理文案：

| 时机 | 文案 |
|---|---|
| 素材就绪 | “素材已就绪。描述目标或选择一种剪辑方式。” |
| 计划生成 | “正在整理剪辑计划，尚未开始分析视频内容。” |
| 待确认 | “计划已准备好：将查找指定内容并生成审核样片。” |
| 审核就绪 | “找到 8 个候选片段，请在右侧审核。” |
| 渲染完成 | “V002 已生成，可预览、精剪或导出。” |

数量、版本和内容必须来自真实状态。不得固定展示“我为你生成了 3 个方案”或“质量通过”。

## 09. Agent 计划、进度与确认

### 9.1 计划摘要与详情

摘要最多包含目标一行、当前状态一行、一个主动作。待确认时主动作“确认并开始”，次动作“查看/修改计划”。点击详情打开既有 `agentPlanDrawer`；桌面优先从左侧展开至 440—520px，详情关闭后恢复原布局。计划抽屉可以是显式模态，但运行进度不得自动弹出覆盖视频。[S1 §9]

详情标签为“计划 / 活动”。计划先显示目标、素材范围、输出形式、执行方式和重要限制，再列步骤。每步默认展示名称、状态、预期输出；模型名、工具参数、质检细节和日志折叠。封面审核、失败链路重试、打开审核样片等入口按真实阶段出现，不常驻整排按钮。

### 9.2 状态与动作

| 状态 | 主展示 | 可用动作 | 禁止行为 |
|---|---|---|---|
| 生成计划中 | 当前阶段、已用时间 | 查看活动、停止规划（能力存在时） | 伪造百分比或启动媒体分析 |
| 待澄清 | 缺失问题与输入 | 补充并更新计划 | 以默认值悄悄越过关键歧义 |
| 待确认 | 计划摘要、范围、输出 | 确认并开始、修改 | 一次确认批准未来所有新计划 |
| 执行中 | 当前步骤、已完成步骤数 | 查看活动、停止计划 | 把步骤比例伪装成真实总耗时进度 |
| 等待审核 | 需要审核的对象 | 打开审核、继续 | 自动略过分步审核 |
| 失败 | 失败步骤与可理解原因 | 重试失败链路、修改规划 | 清空已得到的候选与历史 |
| 停止中 | 正在停止 | 查看活动 | 立即宣称所有后端动作已取消 |
| 已停止 | 已保存结果说明 | 查看已有结果、重新规划 | 将已运行但不可取消的导出隐藏 |

“自动执行到审核样片”和“分步审核”保留原语义；自动执行仍需要先确认计划，且不绕过字幕叠加、封面片头编码、AI 修改应用等原本需要的确认。

### 9.3 进度真实性

只能在已知总量时显示百分比，例如已上传字节/总字节、已处理片段/总片段。模型未知耗时时显示步骤和已运行时间，不显示假 ETA。没有估计依据就不显示剩余时间。全局状态、对话摘要、任务列表引用同一状态源，但只有当前主区域展示完整进度。

## 10. 中央预览、版本选择与播放

### 10.1 工具栏分级

全局 56px 工具栏：左侧任务名（可重命名仅在现有能力支持时）、简短状态；右侧当前上下文主动作和更多菜单。源片/版本切换在预览内部顶部一行完成，不同时保留 `videoViewSelect` 和另一套独立版本状态。[S1 §10—§11、§18]

任务不同阶段的主动作：待确认→“查看计划”；待审核→动作留在右栏“生成版本”，顶部不重复绿色生成；版本就绪→“导出”；精剪→“生成预览”或“导出新版本”，按当前步骤选择一个主按钮，另一个为次按钮。

### 10.2 视频舞台

横竖视频均完整显示，无默认拉伸、裁切或虚假标语。只允许显示真实字幕、当前已确认文本、必要的源片/版本标记。播放出错显示错误说明和重试，不清除当前时间与选择。连续播放候选时明确标记“候选连续预览”，结束后停在最后一个片段，不自动触发合成。

### 10.3 控件

常驻：播放/暂停、上一段/下一段、当前时间/总时长、进度条、音量、倍速、全屏。音量滑杆可在悬停或聚焦音量按钮时展开。上一段/下一段只有候选序列或成片片段序列存在时启用，否则说明不可用。全屏指播放器而非整个编辑项目。

显示顺序：播放按钮 → 段落跳转 → 时间 → 进度 → 音量 → 倍速 → 显示菜单 → 全屏。控件行常规 44px，不叠加第二份默认浏览器工具条。加载失败时保留可操作的其他工作区，不用全页面遮罩。

### 10.4 源片时间与成片时间

这是硬性数据边界：源片 `00:52` 不等于成片 `00:52`。播放器、播放头、字幕与属性面板必须跟随当前 `timeDomain`。点击候选会进入“源片片段预览”，顶部明确显示返回原版本入口；关闭片段预览后恢复之前版本与播放位置。

切换版本时保留各版本最后浏览位置；不能直接把上一版本的绝对秒数用于新版本并假装是同一语义片段。时间映射存在时可提供“查看源片对应位置”，不存在时只切换并说明。视频 loadedmetadata、seeked、失败回调必须检查当前媒体 ID，忽略已经过时的回调。

## 11. 右侧审核、素材、版本与证据

### 11.1 三个标签的内容

| 标签 | 空态 | 有内容时 | 固定底部 |
|---|---|---|---|
| 审核 | “完成分析后，在这里选择需要的内容” | 当前模式结果、选择与校正 | 已选数量、预计时长、主动作 |
| 素材 | “暂无可用候选”或等待分析 | 候选搜索、筛选、来源、可加入对象 | 批量加入/新建事件等上下文动作 |
| 版本 | “生成后将在这里保留各版本” | 版本列表、状态、当前预览 | 当前版本精剪/导出次级入口 |

首次生成结果可提示“审核结果已就绪”，但用户正在输入、拖动或播放时不强行切换标签。焦点留在当前操作处。

### 11.2 选择与统计

选择集合按任务、模式、结果集区分，不能把上次人物结果的 ID 当本次内容结果。筛选隐藏已选项时显示“包含 N 个当前筛选外的已选项”。“全选”必须说明是“当前筛选结果”还是“当前页”，不得默认把尚未载入且未知的结果全部选中。

预估时长与最终成片时长不是一个字段。源区间重叠、转场、片头和变速可能改变输出时长；未计算完成时用“已选源片时长”或“预计”，不能声称最终精确时长。

### 11.3 证据详情

顶部：标题、时间范围、预览按钮；其次：简短理由；再次：对白/屏幕文字/声音/画面等证据分组；最后：技术详情。来源时间点可点击定位，内容不存在时不造空标签。[S1 §12]

“片段证据 / 调整边界”切换保留。边界编辑中显示入点、出点、时长、预览、取消和应用；应用只修改当前选择/草稿，不静默重新导出。删除、下载该片段、加入当前选择均保留，破坏性操作与主动作分组隔开。

## 12. 主时间线：结构、语义与操作

### 12.1 两种时间域，不能混用

主工作台的“源片时间线”表达分析结果、源片选区、镜头与事件分布；“成片时间线”表达当前版本的实际顺序。源片分析视图不提供无业务支持的拖拽重排。需要切分、速度、转场、文本、重排时进入既有二次精剪模块。[S1 §14、§22—§23]

| 视图 | 默认可见轨道 | 按需展开 |
|---|---|---|
| 源片分析 | 画面、音频、事件 | 镜头、AI 提案、人物、说话人、切点、关系线 |
| 人物审核 | 画面、选中人物轨 | 音频、其他人物、镜头 |
| 说话人审核 | 音频、选中说话人轨 | 画面、其他说话人、重叠发言 |
| 成片预览 | 视频、音频、字幕（有字幕时） | 文本、标记、封面/片头 |
| 精剪 | 视频、必要音频、字幕/文本 | 其他已有编辑轨道 |

没有生成字幕时不摆出一条假的字幕轨；不新增音乐轨。现有波形/关键帧切换仍保留，图层菜单可独立开关切点与关系线，默认关闭高噪声关系线。

### 12.2 240px 默认时间线规格

工具栏 36px、总览 20px、标尺 24px、画面/视频 64px、音频 40px、事件或字幕 36px、状态栏 20px，共 240px。没有第三轨时释放给画面或预览，不保留占位空白。增加人物等轨道后内部纵向滚动，标尺与左侧轨道名固定。

左侧轨道标签宽 88px，可根据文本扩到 112px；不能跟随横向时间滚动。缩略图保持原比例，连续帧之间只留 2px 间隔。没有缩略图时使用同色占位并显示“缩略图生成中/不可用”，不能把一张演示图复制到所有时间段。

### 12.3 视觉与命中

播放头使用 `--ct-playhead`，线宽 1—2px，顶部带小手柄；播放头不是整条轨道的高亮红底。当前选区用半透明选中底和左右把手；片段已选用明确边框与选择标记；当前播放片段另外显示播放标记。三种状态可同时存在。

非常短的真实片段不能为了可见性而虚构时间宽度：绘制宽度保持比例，交互命中可以扩展，悬停/键盘聚焦展示实际区间。事件与人物片段过密时聚合或提示放大，不能让点击对象变成随机命中。

### 12.4 时间与边界

内部由适配器统一到安全整数微秒 `TimeUs`，保留原始媒体/服务端时间信息；对外接口仍按现有契约序列化。区间使用左闭右开 `[in, out)`。普通显示采用 `HH:MM:SS.mmm`；简短列表可用 `MM:SS`，精调必须显示毫秒或真实帧定位信息。

入出点满足 `0 ≤ in < out ≤ duration`。最短合法区间以媒体时间基和后端最小可编码约束为准，不能自行固定为 1 秒。拖动结果在提交时重新校验。浏览器 `currentTime` 定位不应被宣称为逐帧精度保证；逐帧功能依赖已有帧时间戳/解码能力，无法保证时显示近似预览，最终边界以渲染结果校验。

### 12.5 交互表

| 操作 | 行为 | 数据影响 |
|---|---|---|
| 点击标尺 | 定位当前时间域 | 不改变选择 |
| 点击事件/镜头 | 定位源片并打开对应详情 | 不自动加入成片 |
| 拖动播放头 | 实时预览，节流媒体 seek | 不创建编辑历史 |
| 拖动总览视窗 | 改变可视区间 | 不移动媒体片段 |
| 缩小/放大 | 以播放头或当前锚点缩放 | 不改变实际时长 |
| 全览 | 适应当前时间域总时长 | 源片与成片分开计算 |
| 缩放到当前事件 | 适应选中事件范围 | 无选中时禁用 |
| 回到播放头 | 滚动使播放头进入视窗 | 不跳转媒体位置 |
| 手动选区 | 创建源片临时范围 | 确认前不加入结果 |
| 拖动边界 | 更新临时范围并显示时间提示 | 释放提交一次编辑操作，不按每帧提交 |
| 输入入点/出点 | 精确改变当前范围 | 非法输入保留原有效值并显示错误 |
| 前移/后移 | 沿用现有选区/排列动作 | 必须标明是移动排序还是时间偏移，不共用模糊文案 |
| 取消选区 | 恢复进入编辑前状态 | 不删除原候选 |
| 确认选区 | 加入当前选择或应用草稿 | 不立即编码 |
| 确认后合成 | 确认后进入既有合成流程 | 需展示本次输入与输出摘要 |

横向滚动、触控板平移、缩放和页面滚动不得相互抢占。播放时视窗采用必要时跟随，用户手动平移后暂停自动跟随并给“跟随播放头”恢复入口。

## 13. 高光审核与多版本生成

右栏审核先展示事件数量与已选时长，下面是事件列表；事件默认折叠内部镜头。被推荐的事件使用一个轻量“推荐”文本标记，不把全部事件涂亮。展开事件后可查看源镜头、理由、字幕/音频证据和实际起止时间。[S1 §15、§17]

事件与镜头的层级必须保留：选择事件等于选择该事件当前有效片段集合；删除内部片段会更新事件状态和时长。仅选择部分镜头时复选框显示半选。替换片段、加入候选、用所选镜头新建事件均复用现有逻辑，不用视觉排序取代真实数据顺序。

候选入口在“素材”标签与审核列表的“查看源镜头候选”中均可到达。宽抽屉用于批量工作，不自动弹出。候选搜索支持标题、对白和说话人；评分和证据字段缺失时相应区域不占位。

生成设置收在右栏底部可展开区：成片形式（合为一条/分别导出）、使用当前选择或 AI 推荐、字幕方式、样式、目标时长、版本数。目标时长只有用户显式指定才作为约束；默认值和允许的版本数量来自现有能力，不在 UI 写死“总是生成三版”。生成按钮文案反映目标，例如“生成 2 个版本”，但数字必须来自实际请求。

格式按已有能力展示 MP4 / H.264、保持源画幅与分辨率、自动码率。审核前后均可返回列表继续修改；已有输出不被新的选择覆盖。自动成片完成后只保留一条助理结果摘要，完整版本到右栏，不再横向堆满主舞台。

## 14. 内容探索、历史结果与成片清单

### 14.1 审核结构

顶部是当前查询的可读描述和结果集切换；主体是匹配片段；底部是选择摘要与生成设置。默认每条展示标题、范围、简短匹配理由；转写、画面人物、说话人、屏幕文字和模型诊断进入详情。[S1 §16]

“检索完整度”“查找依据”“调用诊断”保留，但集中到“检索详情”二级区域。检索不完整属于可解释状态，不一定等于失败；显示尚未覆盖的范围或能力，不能把部分结果标成“已完整找到全部”。

### 14.2 生成与问答设置

保留“完整问答 / 仅问题 / 仅回答 / 问题回答拆分”，仅在当前结果确实有可用问答结构时启用，并说明不可用原因。输出方式为“合成一条 / 每段分别导出”；排序为“源时间 / 自定义 / LLM 推荐”。选择 LLM 排序会进入可审核的推荐顺序，不直接改掉用户手工顺序。

AI 字幕是显式选项，后续仍进入字幕确认；加入成片清单与立即生成是不同动作。底部主动作根据意图显示“加入成片清单”或“生成当前检索视频”，不能同时摆两颗同权重绿色大按钮。

### 14.3 历史与成片清单

每次查询生成独立 `resultSetId`。新检索不会清空历史已保留结果；“恢复历史检索”改变当前活动结果集，不克隆成一份无法追溯的新结果。旧请求晚于新请求返回时，存入对应历史，但不得抢占当前列表。

清单项保留来源查询、素材 ID、源范围、人工边界版本与用户排序。完全相同的区间重复加入时提示已存在；部分重叠时提示“存在重叠”，让用户选择保留两段或调整，不能未经说明自动删除内容。不能仅用标题去重。多素材排序中“源时间”以素材顺序为第一键、源时间为第二键，并在确认中说明素材顺序。

清单支持查看、预览、移除、已有能力支持的排序与生成。删除清单项不删除原检索结果。未生成的选择退出任务前要按已有草稿策略处理，不能伪称服务器已保存。

## 15. 人物审核、校正与提取

人物面板进入“审核”内部页面，保留“校正人物分组 / 选择剪辑目标”两个阶段。识别入口显示在尚未识别或需要重新识别时，结果就绪后不再将识别按钮做成首要动作。[S1 §20、§22]

| 部位 | 定稿规格 |
|---|---|
| 人物列表 | 代表画面、项目内名称、出镜总时长、段数、复核提示 |
| 人物详情 | 出镜片段列表，点击预览；较长列表按需载入 |
| 分组校正 | 合并所选、将所选片段拆为新人物、撤销校正 |
| 目标选择 | 任一人物出现 / 所有人物同时出现 |
| 交叉条件 | 只保留所选人物正在说话的片段 |
| 主动作 | 提取所选人物 |

校正选择与剪辑目标选择分开保存，避免勾选两个人准备合并，却误触“提取两人”。顶部明确显示当前处于哪个阶段。合并/拆分展示影响片段数，成功后保留撤销入口；撤销不能抹掉之后无关编辑，使用既有命令范围或说明不可撤销原因。

“人物正在说话”需要人物与发言关联证据。关联尚未可用时显示解释并走现有分析/确认流程；不能只用“同一时间有声音”冒充确定的发言归属。

人物轨只展开当前选择或当前校正对象，其他人物折叠为数量入口。点击轨道片段与列表互相定位，但不自动改变目标勾选。身份文案只使用“人物 01”或用户主动命名；不因为原型出现“王先生”就推断现实身份。

## 16. 说话人审核与临时跨视频查找

说话人面板结构与人物一致，但图标、样本和行为明确不同：头像位使用音频标记或已有代表样本，不伪造人脸。每个说话人显示名称、发言时长、段数和“试听”；试听同时停止其他样本音频，避免多个声音重叠播放。[S1 §21—§22]

预计人数保留“自动判断、1—12 人”；用户指定后才作为识别配置。校正页保留合并声音、发言归属移动、新建说话人、播放点拆分和撤销。发言列表显示来源范围及重叠/待复核状态，不把并行发言压成互斥单轨。

目标页保留“只查包含这些内容的发言”与三种范围：只保留所选发言、排除所选、所选回答及前置问题。选择问答范围时展示可能包含其他说话人的原因，避免用户误以为过滤失效。

临时跨视频查找收进“更多：使用参考声音查找其他视频”。流程独立展示参考声音、目标视频、本次范围、开始、取消和会话结果。进入时说明这是一次会话范围的查找，不新增永久声纹库或跨项目默认身份绑定。没有目标素材权限或后端能力时，不显示可执行的伪按钮。

声音校正成功、轨道更新与片段审核三者使用同一结果修订号。后端返回较旧修订时不能覆盖刚完成的人工归属修正。

## 17. 成片版本、下载与导出

### 17.1 版本列表

版本卡采用低高度列表，而不是三张广告卡：缩略图、V001 等编号、可读标题、时长、片段数、生成时间、状态。状态必须区分“生成中、可预览、需复核、失败、已保留”。“质量通过”仅当真实质量检查给出结论时显示。[S1 §18、§25]

顶部紧凑选择器和右栏版本列表引用同一 `activeOutputId`。版本数量较多时选择器改为下拉；禁止因为只画了 V1/V2/V3 就隐藏第四版。版本点击预览不自动将其设为最终封面版本或正式导出目标。

右栏每个版本保留“精剪、下载、保留到成片库、重新选择素材”的相应入口；低频动作放更多菜单。“已保留”是保存到成片库的业务状态，不等于文件生成成功。

### 17.2 导出流程

```text
选择明确的版本/草稿修订 → 预检 → 必要的字幕/封面确认
→ 展示本次导出摘要 → 提交 → 可追踪生成状态 → 新版本/文件就绪
```

已有可下载文件的“下载 MP4”是直接下载，不应强制重复编码；“生成高清新版本”“生成封面片头版”是编码任务，名称与确认必须不同。下载封面 JPG、字幕 SRT、发布包继续保留，仅在文件可用时启用。[S1 §10、§18—§19、§24、§30]

导出摘要包含：任务、输入版本/草稿修订、输出名称、输出形式、视频编码与画幅策略、字幕方式、是否加片头、排序与预计时长。没有后端支持的分辨率、帧率、码率选择不得摆成可选高级参数。

### 17.3 预检与版本保护

| 条件 | 处理 |
|---|---|
| 没有有效片段 | 阻止，定位到审核/时间线 |
| 素材缺失或边界越界 | 阻止，列出具体片段 |
| 字幕待确认且本次要烧录 | 转字幕校对，不静默烧录 |
| 允许叠加原字幕尚未确认 | 阻止相关字幕烧录 |
| 封面未选但仅导出视频 | 不因无关封面强制阻止 |
| 要生成封面片头版但片头未确认 | 展示确认与时长 |
| 质量需复核 | 保留原有阻塞/提示级别，清楚说明；不自行扩大或取消限制 |
| 同一修订导出请求正在进行 | 显示现有任务，防止误重复提交 |

提交后绑定不可变输入快照。快照必须保留现有引擎需要的完整编辑输入，包括速度、转场、声音、文本、字幕和封面；源片范围列表只是 UI 摘要，不能取代完整渲染参数。已有服务支持不可变修订引用时可引用该修订，否则由适配器序列化完整引擎输入。用户继续编辑产生新草稿修订，不影响正在渲染的那一版。渲染完成提示“基于草稿 rN 生成”，不能把其标成当前 rN+1 的结果。取消操作显示停止中，直到服务端确认；不可取消的任务要如实显示仍在运行。

## 18. 二次精剪：统一外观、保留编辑能力

### 18.1 容器与模式切换

复用 `secondaryEditor` 的现有功能，视觉上改为工作台内的“精剪模式”，不要求重写编辑引擎。桌面为素材库、预览/成片时间线、属性检查器三栏。左侧“助理 / 素材”切换保持原对话，不在精剪时永久删除助理入口。右侧属性取代普通审核栏，不能同时挤出第四列。[S1 §23]

进入时锁定所编辑版本并创建/恢复对应草稿。标题显示“精剪 · V002”，旁边显示真实保存状态。退出时回到该版本的普通预览；存在未保存修改时提供“继续编辑 / 保存后退出 / 放弃本次未保存修改”，实际可选项取决于已有保存能力。

### 18.2 素材库与预览

素材库保留模式素材/源视频范围标签，搜索、推荐/时间线/已保留/其他筛选、插入位置、跟随播放头、自定义源片入出点与片段名称。插入位置必须明确为“当前片段后”“播放头处”等真实支持的动作，不能只写“应用”。

预览保留“成片顺序 / 源视频”切换、添加/删除文本、素材和属性面板开关、当前时间、独立文本层、字幕预览编辑、播放与全屏。文本层与字幕层不是同一数据类型，不能因为都显示文字就共用删除事件。

拖动字幕/文本位置时显示安全区；缩放预览只改变显示比例，不改变实际输出分辨率。位置储存使用已有输出画布坐标或归一化坐标，通过适配器转换，不直接保存浏览器绝对像素。

### 18.3 编辑操作

保留拖拽重排、边界裁剪、多选、切分、裁左/裁右、删除、复制、标记、吸附、逐帧、缩放、撤销/重做、预览样片与高清新版本导出。Shift+拖边仍用于现有滚动裁剪语义；普通拖边与滚动裁剪必须有不同反馈，不得为统一组件改变原有业务含义。

一次连续拖动只形成一个撤销步骤；释放前保持预览草稿，取消拖拽还原；拖拽到非法位置显示禁止提示，不产生半个移动命令。吸附默认沿用现有用户设置，命中时显示明确参考线，不吸附到隐藏且不可解释的对象。

### 18.4 属性检查器

| 标签 | 保留内容 | 校验与保存 |
|---|---|---|
| 片段 | 源入出点、时长、速度、转场、转场时长、声音衔接、音量、静音、淡入淡出 | 参数选项来自已有能力；保存与取消分开；转场/淡入淡出不得超过有效边界与后端约束 |
| 字幕 | 导出添加字幕、建立校对、当前片段字幕状态、恢复位置大小、拆分、合并、删除 | 修改后撤销之前的最终确认状态 |
| AI 修改 | 自然语言、已有快捷示例、修改预览、提案 | 必须显示变更清单与基准修订；未确认不执行 |
| 导出 | 版本名、预检、画幅/编码策略 | 始终创建新版本，不覆盖原输入 |

多选时共有属性可批量编辑，不同值显示“多个值”；没有批量支持的字段禁用并说明，不能把第一项的值当全部对象的值写回。

### 18.5 AI 修改提案

提案至少展示修改对象、动作、修改前后、影响时长、无法执行项和输入草稿修订号。按钮“应用这些修改”与“取消”分开。用户在提案产生后继续手动修改时，旧提案标记过期；重新校验/重新生成后才能应用，不静默覆盖较新草稿。

模型只能提出界面支持、后端允许的命令；未知命令以“暂不支持”显示，不能通过渲染 UI 文本执行任意脚本、任意路径或隐藏参数。

## 19. 字幕校对与最终确认

字幕校对沿用专门 `subtitleReview`，改为宽屏左右结构：左边预览与样式，右边逐条校对；窄屏上下排列。顶部显示所处理的版本与草稿修订，底部固定保存状态、保存草稿和“确认字幕并继续导出”。[S1 §24]

预览显示真实视频、当前字幕、安全区和字号/位置摘要。原视频存在字幕的确认区独立可见：“新字幕会叠加到原画面，不能自动移除原字幕”；保留允许叠加复选框及原有阻塞规则，不把这条风险折叠到看不到的更多菜单。

字幕行默认展示序号、成片入出点、文本和试听定位；选中行再展开 AI 建议与拆分、合并、删除等动作。AI 建议展示风险、建议文本、理由和可用证据；接受修改与保留原文并列，不能自动覆盖。批量接受低风险建议必须说明影响数量和规则，并可撤销。

“AI 全文校对”产生建议，不等于确认字幕。任何字幕文本、时间、位置或烧录样式发生与输出有关的修改后，确认状态回到待确认，且绑定修订号。字幕已确认后新增视频片段或改变顺序/速度，也要重新建立映射并使相关确认失效，不能沿用旧时间码直接导出。

字号加减、顶部/中央/底部预设、自然语言样式命令保留。命令应用后显示可读结果或错误；不支持的要求不能看似成功。字幕越界、空文本、出点小于入点、超出成片范围在行内提示；时间冲突按现有字幕引擎规则处理，不能自动吞字。

## 20. 封面与片头轨道

封面功能入口位于版本更多菜单、相应计划步骤与时间线图层。封面候选、封面编辑、当前选定、保存状态都进入 `timelineCoverTrack` 的统一面板。此模式允许临时增加轨道高度，但不挤掉播放器。[S1 §19]

**区分两个对象。** 封面图是当前选用的一张图片；片头是插入成片时间轴并占用时长的视频段。选择封面候选后按钮是“保存为当前封面”，旁边说明“不会重新生成视频”。只有“生成封面片头版”才进入编码确认。

保留候选方向、画幅、分数等已有信息，但缺失字段不造值。片头默认时长沿用当前业务的 1 秒预设，并允许在已有编辑范围内调整；确认摘要显示本次真实时长。若修改时长使预设不再是 1 秒，按钮不能仍写“生成 1 秒片头版”。

封面选择与版本关联明确。对 V002 选封面不能自动覆盖 V001；封面下载使用当前已保存封面，草稿未保存时提示先保存或明确下载草稿，不混用。

## 21. 任务列表、成片库与全局导航

### 21.1 导航整合

现有 `appSidebar` 从独立 72px 轨道改为左栏内导航。品牌点击首页；“工作区”进入当前任务，无当前任务时禁用；“新建”沿用创建流程；“任务”打开任务抽屉；“成片”进入成片库；服务与设置位于左栏底部。任务和成片数量仅在有意义时显示小型数字，不同时加彩色圆点、边线和徽章。[S1 §4]

### 21.2 任务抽屉

桌面宽 360—420px；保留搜索、全部/进行中/待确认筛选、数量、加载更多、任务打开、允许时删除。每行显示名称、状态、最近更新时间；只有运行中的任务显示进度。未加载完时不宣称“共 N 个”就是全部数量，除非接口提供准确总量。[S1 §5]

任务切换前处理当前未保存编辑，但不能阻止用户查看其他任务的运行状态。删除遵循现有允许状态，先确认影响；删除任务与删除成片库文件的关系要从现有后端获取并在确认中说明，不自行假定级联删除。

### 21.3 成片库

采用自适应网格或宽列表，卡片至少展示视频、时长、版本、标题、来源任务、日期、文件大小。保留搜索、排序、播放、下载和删除确认。搜索无匹配与库为空是两个空态；读取失败不能显示“还没有成片”。[S1 §25]

同一时间只允许一个库内视频播放音频。离开成片库停止当前预览。返回工作区恢复原任务、选中版本和面板宽度，不重置为新建页。浏览器前进/后退与现有 `popstate` 行为保持一致。

## 22. 设置、服务状态与 Skills / Plugins

### 22.1 设置架构

设置使用独立页面，不压缩到 288px 右栏。左侧分组导航为“模型配置、运行环境、Agent 能力”；模型配置内部区分视觉分析、剪辑规划、Agent 模型，文案解释职责，保留所有现有表单。[S1 §26—§27]

| 配置组 | 必须保留 |
|---|---|
| 视觉分析 | 服务商、API Key 显隐、接口地址、连接验证/读取模型、模型选择/手填 ID、思考模式、JSON 输出 |
| 剪辑规划 | 复用视觉配置/独立配置、对应配置项、保存与放弃 |
| Agent 模型 | 服务商、Key、地址、验证、模型、思考模式、工具调用探测并保存 |
| 运行环境 | 视觉/规划/富语音模型、语音设备、视觉后端、输出策略、本地渲染及服务状态 |

API Key 默认掩码；日志、Toast、截图用例不能包含真实密钥。验证连接的临时输入不能被错误文案回显。接口地址允许现有支持的本地服务情形，不以无依据的强制 HTTPS 规则破坏自部署；公开远端与本地地址的风险提示要区分。

未保存修改显示真实 dirty 状态。验证连接成功不等于配置已保存；模型列表读取失败时保留手动模型 ID 入口。切换“复用/独立”不得立即丢弃未保存配置；返回前有明确保存/放弃处理。

### 22.2 Skills

保留自然语言生成 Skill 草稿、模拟规划、安装标准 Skill ZIP、列表中的名称/版本/来源/状态/描述、审核启用和禁用。草稿模拟结果必须明确“不执行实际剪辑任务”，不能把模拟规划当已安装能力。

### 22.3 Plugins

Plugins 单独显示权限风险：它们是受信任运行代码，不是普通文本模板。先检查 ZIP，展示来源、版本、工具列表、权限警告和信任复选框，再启用。默认不勾选信任；批量样式改造不能使确认失效或自动触发启用。失败后展示具体错误并保持禁用状态。

技能/插件启停后刷新能力目录，当前计划若依赖被禁用能力，应提示重新规划或恢复能力，不能让已显示的可执行计划继续误导用户。

## 23. 全局弹窗、Toast、错误与文案

### 23.1 层级与焦点

统一覆盖层层级：基础内容 0；固定标题/动作区 20；菜单 100；非模态侧面板 200；模态遮罩 400；模态窗口 410；模态内部菜单 420；全局紧急提示 500。具体数字只在统一 token 中定义，不能各组件随意用 999999。

同一时刻只有最上层模态接收键盘焦点。打开时把焦点放到标题或第一个合理控件，关闭后返回触发处。Esc 只处理最深一层：先关菜单，再取消拖拽/临时编辑，再关闭详情，最后处理有未保存内容的确认。不能一次 Esc 关闭所有层并丢失编辑。

### 23.2 确认弹窗

普通确认宽 440px，带排序/选择列表的确认宽 640px，最大高度为视口减 48px。内容先说明结果，再列影响范围，最后放必要警告。标题用“删除这个任务？”“生成封面片头版？”等具体动作，不仅写“确认操作”。[S1 §28]

高风险弹窗默认焦点放在取消/返回，确认按钮文案写实际动作。保留合成顺序选择、输入弹窗与选项输入能力。长列表内部滚动、页脚固定，不能因为滚到底才能看到风险。

### 23.3 Toast 与就地错误

成功 Toast 约 4 秒自动消失；可恢复错误约 8 秒或用户关闭；阻塞错误必须就地常驻，不能只靠 Toast。提示放到不会遮住时间线主操作的位置，默认右上靠内；多个相同错误合并计数。含撤销动作的提示不得在用户聚焦或悬停时自动消失。

用户可处理的错误使用“原因＋保留了什么＋下一步”。例如：“合成失败，所选片段已保留。检查服务后可重新生成。”技术堆栈收进详情，不能原样暴露密钥、访问令牌、完整私有路径或无关内部数据。

### 23.4 访问令牌

保留当前标签页会话范围存储，输入采用密码字段，不写进地址栏、不拼进可分享链接、不写入普通日志。不得因为新增布局持久化而把令牌与布局一起写入长期本地存储。[S1 §28]

### 23.5 文案统一

| 不采用 | 采用 |
|---|---|
| AI 智能超级精彩剪辑结果 | 候选片段 / 高光事件 |
| 应用、继续（缺少对象） | 加入事件 / 生成版本 / 确认并开始 |
| 完成（实际上只是上传） | 素材已就绪 |
| 100%（但后台仍处理） | 已完成 N 个步骤；正在生成文件 |
| 操作失败 | 明确的失败对象、原因与重试入口 |
| 新建聊天 | 新建任务 |
| 一律称素材 | 明确源视频、候选片段、成片版本或草稿 |

## 24. 前端状态、数据契约与异步一致性

### 24.1 不用一个字符串控制整个工作台

任务、播放器、编辑草稿、导出和连接状态必须分开。任务正在分析时播放器仍可能正常播放；一个版本导出失败不等于整个任务失败。配套 `ui-contracts.ts` 是建议的前端归一化模型，不是声称后端已经返回这些字段。

| 状态域 | 关键字段 | 说明 |
|---|---|---|
| 导航 | `view, taskId, editorSourceOutputId` | 首页/工作台/精剪/成片库/设置 |
| 任务 | `phase, workflow, activePlanId, planRevision` | 草稿、规划、待确认、运行、待审核等 |
| 结果 | `activeResultSetId, resultSets` | 保留历史与当前结果，不能直接用最新数组覆盖全部 |
| 选择 | `contextKey, selectedIds, focusedId` | 勾选与当前预览分离，按结果集隔离 |
| 播放器 | `mediaRef, timeDomain, positionUs, status` | 源片/成片明确，错误不抹掉身份 |
| 时间线 | `viewDomain, visibleRange, playheadUs, tracks` | 源片与成片的可视区间独立 |
| 草稿 | `draftId, revision, dirty, saveState` | 未保存、保存中、已保存、失败、本地草稿 |
| AI 提案 | `proposalId, baseRevision, commands, status` | 过期提案不能直接应用 |
| 字幕确认 | `subtitleRevision, confirmedRevision, editRevision` | 绑定字幕内容及剪辑映射 |
| 导出 | `requestId, inputSnapshot, status, progress` | 输入快照不可变，输出不覆盖历史 |
| 布局 | `breakpoint, paneSizes, activeRightTab` | 与业务状态隔离，尺寸需校验 |
| 连接 | `status, lastEventAt, retryState` | 断线不自动把任务改为失败或已停止 |

### 24.2 状态转移与确认关口

```text
任务草稿 → 规划中 → 待澄清 / 待确认
待确认 --确认当前计划修订--> 执行中
执行中 → 待审核 / 部分失败 / 已停止 / 结果就绪
待审核 --确认选择--> 生成中 → 版本就绪 / 生成失败
版本就绪 → 精剪草稿 → AI 修改提案 → 确认应用 → 新草稿修订
新草稿修订 → 必要字幕确认 → 导出预检 → 渲染 → 新版本
```

修改计划必须产生新修订，旧确认不再有效；修改选择使其相关生成摘要过期；修改字幕或时间映射使确认过期；修改封面图不必无条件让无关视频编码结果失效。状态失效范围应准确，避免每次改标题都要求重新分析全片。

### 24.3 异步与竞态规则

每个请求关联 `taskId + requestId`，结果关联 `resultSetId / planRevision / draftRevision`。切换任务、切换媒体、重新查询或销毁组件时取消可取消请求；无法取消的晚返回结果只能更新自己的记录，不能抢占当前工作区。

实时事件若有序号/修订，拒绝旧序号覆盖新状态。没有事件序号的接口在重连时主动读取当前任务快照并校正，不靠前端猜顺序。断线提示“连接中断，后台任务状态待同步”，不擅自显示任务停止。

点击确认、提交、导出后前端立即锁定该动作实例，防双击。服务端支持幂等键时通过适配器传入；不支持时，遇到“请求可能已到达但响应丢失”，先查询已有任务再决定是否重试，不宣称客户端按钮禁用就实现了后端幂等。

### 24.4 保存与恢复

布局可长期保存：宽度、高度、折叠状态、当前断点、图层偏好；保存前校验数值范围，换屏幕后重新 clamp。不得保存密钥、访问令牌、原始语音样本、未经许可的跨视频身份索引。

任务草稿、选择与字幕的恢复沿用既有保存机制。若只有内存或本地暂存，文案写“本地草稿”，不能写“已同步”。保存失败保留用户输入并显式提示，关闭前再次确认。恢复草稿时校验素材和版本是否仍存在，不把失效 ID 悄悄换成别的媒体。

浏览器刷新、返回、关闭弹窗、关闭精剪和切换任务使用同一未保存判断来源。`beforeunload` 只作为补充，不代替应用内保护。

### 24.5 能力开关与未知值

现有盘点没有列出的参数由适配器返回能力：允许格式、容量、可用速度/转场、可取消步骤、支持的下载类型、保存方式、代理预览、精确帧定位等。未知不是支持，也不是永久不支持：首次加载显示适当等待或解释，查询失败显示重试。

不能为了完成画面把未知数量设为 0、未知时长设为 60 秒、未知置信度设为 98%、未知质量检查设为通过。允许未知值，并为其设计显示状态。

## 25. 键盘、无障碍与操作安全

### 25.1 快捷键作用域

快捷键只在对应工作区激活，且必须先排除输入框、textarea、contenteditable、输入法组词与打开的模态。Space 在聚焦按钮上仍遵守按钮本身的激活语义，不能同时触发全局播放器。

| 快捷键 | 工作区 | 动作 |
|---|---|---|
| Enter / Shift+Enter | 对话输入 | 发送 / 换行，组词期间不发送 |
| Space | 播放器或时间线区域 | 播放/暂停当前媒体 |
| Ctrl+B；macOS 对应 Cmd+B | 精剪，非文本输入 | 切分；沿用原有平台映射并在面板显示实际组合 |
| Q / W | 精剪时间线 | 裁左 / 裁右 |
| `,` / `.` | 支持逐帧的精剪区域 | 后退 / 前进一帧 |
| `+` / `-` | 时间线区域 | 放大 / 缩小 |
| `/` | 时间线区域 | 适应全片 |
| Ctrl/Cmd+Z | 可撤销编辑区域 | 撤销；文本编辑时保留原生文本撤销 |
| Ctrl/Cmd+Shift+Z | 可撤销编辑区域 | 重做；与项目现有平台逻辑保持一致 |
| Shift+点击 | 可多选列表/轨道 | 连续选择 |
| Shift+拖边 | 精剪边界 | 现有滚动裁剪 |
| Esc | 当前最深层 | 关闭菜单、取消临时操作或返回，不能穿透 |

Delete/Backspace 只有精剪片段区域明确拥有焦点且存在选中对象时才可删除；不在页面级监听后无条件删除片段。删除后的焦点落到相邻可用对象，不落到页面顶部。

### 25.2 可访问组件

图标按钮提供可访问名称；标签页、菜单、复选框、半选框、对话框和分隔器使用正确语义。模态有标题关联、焦点约束和返回焦点。Toast 使用非打断通知，阻塞错误使用明确警报但不要重复朗读几十次。

时间线不能只靠 Canvas：至少提供当前选中对象、时间范围、可用操作与片段列表的可访问等价表示。键盘能够选择片段、调整入出点、预览、加入/移除和确认。人物/说话人不能只用颜色区别，应同时有名称、编号和状态。

浏览器 200% 缩放时不能丢失关键输入或确认按钮；允许切换至窄屏布局。触摸命中至少 44px，紧密轨道可通过上下文表单提供等价操作。hover 提示必须可经键盘聚焦触发，不能是唯一说明来源。

## 26. 性能、媒体资源与安全实现

### 26.1 性能预算是目标，不是已测结果

在开发声明的基准机器、浏览器、媒体与数据量下测量。UI 点击反馈目标不超过 100ms；拖拽视觉反馈争取每帧不超过 16.7ms，不能以此承诺后端分析或渲染速度。记录实际测量条件和结果，未测项不得标为通过。

长候选、字幕、人物片段和活动日志采用分页或虚拟列表，建议超过 200 项时进行专项测试。不能一次为一小时视频创建每帧一个 DOM。时间线绘制以可视区间为核心，缩略图缓存按素材 ID、时间和资源版本区分，不能跨素材串图。

波形 Canvas 按实际像素尺寸与设备像素比绘制，resize 后重绘；滚动时复用缓存，不对每次鼠标移动重算全部波形。播放头用独立层更新，避免每帧重新渲染完整侧栏。指针移动只更新临时交互状态，业务提交发生在结束点。

### 26.2 媒体生命周期

预览媒体切换时停止旧媒体和旧监听器，释放无用 Object URL、定时器与拖拽状态。对话、人物试听、成片库和主播放器共享“谁拥有音频播放”的控制规则，默认不同时播放多个声音。

缩略图、波形、字幕某一项失败时局部降级，其余功能继续。源媒体读取失败与成片生成失败使用不同错误入口。视频资源失效后可重取链接的能力由既有服务决定，不通过猜 URL 或重写文件名获取媒体。

### 26.3 输出与安全边界

模型返回文本默认按文本显示；Markdown 渲染使用项目已有安全处理，不插入未清洗 HTML。工具日志、插件描述、字幕、用户文件名都不能直接进入 `innerHTML`。UI 不执行模型提供的任意脚本或路径。

状态埋点只记录必要的事件类型、耗时、匿名任务关联和错误类型，不默认上传原始对话、字幕全文、视频画面、密钥或声音样本。用户上传素材与允许调用外部模型的边界沿用现有权限和计划确认，不因重设计扩大数据发送范围。

## 28. 开发顺序、交付物与完成定义

### 28.1 分阶段实施

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| P0 基线冻结 | 盘点模板、动态渲染入口、状态源、真实资源、功能截图；建立回归样本 | 所有现有主路径有记录，关键能力与未知项被标识 |

### 28.2 仓库核实清单

开工时核实：实际前端技术栈；各挂载点是 id 还是 class；动态模板输出位置；当前媒体与版本的唯一状态源；已有上传限制；参数枚举；保存方式；取消/重试语义；真实资源路径；字幕映射；插件信任控制。源码核实不改变本文已明确的视觉方向，只决定适配实现与能力开关。

本文已给出未知能力的处理规则，开发不应因没有虚构一个接口地址就停下全部 UI 工作。可以先实现组件与状态壳，但在真实接入前，未支持功能必须标注并不可伪执行。

### 28.3 开发实际需交付

交付修改后的源码、变更说明、组件/状态适配映射、已执行验收记录、已知问题及回滚方式。验收记录必须区分“通过、失败、未执行、不适用及原因”。截图仅辅助视觉核对，不能替代点击、输入、恢复与导出验证。

**完成定义：** 所有核心路径可操作；四模式和高级能力可达；最终界面符合 A 版色温与层级；无无意义占位按钮；无数据丢失或版本覆盖；无重复 ID；异步结果不会串任务；所有阻塞性用例通过。本文附件本身不代表这些实施验收已经完成。
