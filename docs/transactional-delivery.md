# 精剪、导出与 Agent 执行一致性

本轮实现记录，取代 `流程修复验收.md` 中关于旧导出请求兼容性的说明。既有视频、版本和数据库记录不清空。

## 修改对应关系

| 问题 | 实现 |
| --- | --- |
| 精剪异步操作串任务 | 打开、提案创建/选择/应用/取消、字幕校对、预览轮询、正式导出校验任务 ID、草稿 ID、修订和编辑器激活令牌；旧响应也不能改变新页面的错误或忙碌状态。 |
| 正式导出遗漏文字层或画幅 | `app/render_spec.py` 维护带版本号和 SHA-256 的完整规格；包含有序片段及其声音/速度/转场设置、插入镜头、章节、剪辑策略、文字层、画幅和字幕快照。正式渲染以冻结规格为准。 |
| 字幕在排队期间改变 | 在确认/入队时复制字幕内容、修订、布局与样式；真实范围、顺序、速度和静音裁剪变化必须重新校对，规范化默认值不造成误拒绝。 |
| 保存失败留下脏内存 | 主要精剪修改使用隔离工作副本；`update_job` 提交后发布；兼容的原地写入失败时恢复 SQLite 已提交快照，数据库整体不可读时使用提交缓存。备份或指标失败不撤销已提交保存。 |
| 提交后的附属步骤失败会删除成片 | 版本提交即成为不可回滚的边界；输出文件保留。清单、结果消息、代理和选择篮清理带待补偿标记，可由启动维护重试，重复补偿不重复结果消息，也不清除更新后的选择篮。 |
| 并行导出互相覆盖 | 操作分别记录状态/进度/结果；版本提交合并当前版本集合；失败不恢复旧输出快照；后台完成不覆盖更新后的当前版本选择。 |
| 入库复制阻塞所有任务 | 复制前持久化操作并固定来源，文件复制在全局任务锁之外；复制期间阻止相关删除；元数据临时文件原子发布，完成后重新校验输出身份。 |
| 旧 Agent 样片状态压过正式结果 | 呈现层结合活动操作、结果版本以及草稿/计划来源判断；旧流程的正式结果不能覆盖新计划的待审样片。 |
| Plugin 超时后重复执行 | Node 独立 SQLite 操作日志记录请求指纹、状态、结果和错误；重复 ID 返回同一记录，内容冲突返回 409；Python 超时后查询记录，不盲目重发执行。 |
| Plugin 版本号未变但代码变了 | 计划、审批、执行和重新规划复用都绑定版本号、内容哈希及目录树哈希；执行前再次检查源码；旧无哈希审批不复用。 |
| Agent 镜像缺运行模块 | Docker 复制全部运行时 `.mjs` 文件，构建时检查 Node 原生 SQLite 和入口语法。 |

竖屏正式渲染使用同一画幅/定位参数，但采用交付分辨率和编码质量；9:16 正式画布为 1080×1920，审核代理为 540×960。

## 接口与恢复规则

正式导出仍使用原有 `/api/jobs/{job_id}/output-versions/{version_id}/finalize` 路由。

- 请求必须明确传入 `specVersion: 1`、`outputFilename` 和服务端返回的 `outputRevision`。
- 烧录字幕另须 `subtitleDraftId`、`subtitleDraftRevision`、`subtitleDraftHash`；确认字幕接口返回 `draft.contentHash`。哈希不可由客户端猜测。
- 缺少确认身份或无法还原文字/画幅的旧样片返回 409 / `export_confirmation_required`，不再静默取第一条文件或补默认画幅。
- 新精剪预览和导出在入队前冻结规格。没有冻结规格的旧正式导出/精剪队列要求重新确认；分析队列仍按原流程恢复。
- 导出返回 `operationId`；`GET /api/jobs/{job_id}/operations/{operation_id}` 返回状态、结果版本、错误和可重试性，不暴露持久队列内部参数。
- Plugin 操作结果为 `running` 或 `uncertain` 时，界面提供“核实操作状态”，只查询日志；不能直接确认其成功或自动再次执行。
- 成片库操作若被服务重启打断，记录为 `uncertain`，需核实库中的实际文件。已复制的独立库文件不因任务删除而被清理。

## 部署与验证边界

同时重启 FastAPI 和 Agent 服务，再刷新页面。没有自动重启当前用户服务，也没有操作既有素材。

Agent 需要支持 `node:sqlite` 的 Node 22；Docker 基础镜像为 Node 22。原生 SQLite 可能打印实验性功能提示。操作日志以租约阻止两个服务同时接管同一日志；异常终止后最多等待约 30 秒租约失效，未完成工具操作保持待核实而非重放。

回归覆盖真实接口鉴权和 Plugin 幂等执行、浏览器交互隔离、SQLite 故障、队列恢复、复制期间锁释放、提交后清单故障、并行失败，以及临时合成视频的文字层和竖屏导出。不使用云模型或用户视频。

2026-09-10 验收：后端完整测试 1086 项通过（独立临时数据目录、模型离线）；`npm run lint` 通过，Agent 入口和操作日志模块的 Node 语法检查通过。

前端最后一轮全量运行 178 项，177 项通过；剩余一项是测试错误地将没有质检报告的既有版本预期为 `quality-passed`。核实测试数据后改为 `quality-pending`，该浏览器用例完整复测通过。此前发现的按钮文案契约、移动端入口和编辑器隔离测试也已通过。此处记录全量运行与定向复测的实际结果，不将其合称为一次全量零失败运行。

当前环境没有 Docker daemon，容器构建/启动验收未执行；已验证本机真实 Node 服务的启动、鉴权、插件执行及操作日志。云模型长流程和生产部署验收仍需在部署环境进行。
