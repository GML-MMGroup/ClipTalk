# 旧主题覆盖清理 · 2026-09-09

## 结论

生产页面的主题异常来自多轮样式叠加：同一文件不断追加覆盖段、不同文件重复定义相同规则，以及旧浅色规则借助 ID、`:is()` 和 `!important` 压过最新版绿色主题。已经删除确认冗余的声明和已定位的旧主题冲突，没有新增另一张覆盖样式表。

## 检查范围

核对 `static/index.html` 的 12 张生产样式表及其加载顺序、前端脚本中的工作台状态和动态展示逻辑、资源引用与现有浏览器回归用例。第三方依赖自带的示例/导出主题不进入生产页面，保留依赖内容。动态生成的剪辑、审核、错误、进度和响应式状态不能仅凭首页未使用就删除。

## 已处理的覆盖来源

| 来源 | 问题 | 处理 |
| --- | --- | --- |
| `theme.css` | 后置 quiet v2 色板及局部色板覆盖了顶部已接入绿色主题的 `--pw-*` 变量 | 删除 26 条竞争色板声明，保留对 `--ct-*` 的统一引用 |
| 多张 CSS | 同选择器、同属性、同条件的旧声明被后续声明完全覆盖 | 删除 3,482 条可证明冗余的声明及空规则 |
| `editing-workspace.css` | 打开二次精剪时，旧 `body:has(...)` 规则把页面切回浅色 | 删除这组旧主题规则；二次精剪由 `secondary-editor-focus.css` 管理 |
| `app-shell.css`、`editing-workspace.css` | 高优先级浅色时间线工具栏、按钮、版本选择框覆盖当前工作台颜色 | 删除这些旧颜色、背景、边框色和阴影声明，保留布局 |
| `editing-workspace.css` | 下载与重试按钮仍用橙色，播放器说明文字沿用浅色界面的灰色 | 在现有规则中改用统一主题变量 |
| `theme.css` | `:is(button, #playerClock)` 将时钟 ID 的权重赋给所有播放器按钮，覆盖重试按钮文字色 | 改用 `:where(...)`，恢复组件自身文字颜色与对比度 |
| 多张旧 CSS | `color-scheme: light` 让原生下拉菜单等控件沿用浅色主题 | 删除 6 条浅色声明，继承统一深色模式；加入防回归检查 |
| `static/index.html` | 浏览器缓存可能继续使用清理前 CSS | 更新 CSS 资源版本号 |

## 防止再次堆叠

- `tools/audit_css_cascade.mjs` 按生产加载顺序比较相同选择器、属性和条件；尊重 `!important`，跳过层、作用域、嵌套、动画、厂商前缀及 Chromium 不支持的值，不猜测简写属性或未使用选择器。
- `npm run audit:css` 检查重复覆盖，已接入 `npm run lint`。`node tools/audit_css_cascade.mjs --write --report /tmp/css-report.json` 可执行同类清理并输出逐条记录。
- `tools/audit_frontend_ownership.py` 检查关键色板变量的唯一归属，并继续阻止已退役资源回归生产页面。
- 回归用例改为验证生产加载链中的最新版主题，增加重试按钮文字/背景和成片选择框背景检查。
