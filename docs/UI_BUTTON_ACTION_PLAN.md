# 按钮行为一致性修复计划

## 目标和边界

让按钮实际打开其名称承诺的内容，不再只定位隐藏节点或在后台播放。沿用已有面板、弹窗和主题，不调整生成逻辑，不改动 `app/main.py`、任务文件或模型配置。

## 实施顺序与验收

1. **方案归属**：统一方案详情入口，记录任务及方案身份。旧卡片打开对应快照，标注历史只读；不能确认、重试或修改新方案。轮询不得将正在阅读的历史详情替换为新方案。
2. **待办和确认跳转**：待办按动作类型打开方案、封面检查或质量提醒；失败步骤、核对计划和处理确认使用统一入口。查看操作不能自动批准、重试、生成或导出；内容不存在时显示明确原因。
3. **窄屏预览**：播放样片、选择版本或定位源片段时切到预览页，显示所选视频或位置；自动恢复页面时不擅自切换用户正在使用的页签。
4. **异常反馈**：缺少预览/主操作时只显示一个详情入口，解释结果数据缺失。桌面和手机保持一致，不能把不可执行操作装成可用按钮。
5. **验证**：补充历史方案、跨任务隔离、后台刷新、待办只读、异常数据、窄屏跳转测试。已有任务仅允许 GET/HEAD/OPTIONS，验证入口但不执行生成、导出、删除或确认。

## 交付检查

- 每个新入口都能打开内容；打开、关闭不带动整个工作区移动。
- 历史方案正文与所点卡片一致，没有当前方案的操作按钮。
- 质量提醒能看到提醒，缺少片段时间时不虚构定位。
- 390px、1024px 与桌面宽度均可访问预览和详情。
- 前端静态检查、相关回归测试和重复样式检查通过。

## 执行结果

以上五项均已落实。采用现有界面改造技能的局部修改方式，复用方案抽屉和封面时间轴，没有新增平行弹窗。

- 历史卡片显示“查看历史方案”，移除可执行旧操作；历史详情只读，当前任务轮询不会替换其正文。跨任务打开旧入口会提示重新打开对应任务。
- 待办按动作打开对应位置；封面审核进入现有时间轴，质量提醒进入方案内的质量区；失败与确认入口不再引用隐藏容器。查看不代表批准、重试或导出。
- 窄屏主动播放/定位切换到播放器；被动恢复媒体不切换用户所在页签。
- 缺少预览时显示“预览暂不可用”和原因，桌面、手机均只保留一个详情按钮。

验证：工作区/布局/样式 106 项、Agent/聊天 44 项及新增工作区跳转 2 项，共 152 项相关测试通过；重点场景最后复核通过。前端静态检查、脚本语法检查、修改格式检查通过，重复样式告警为 0。

真实任务只读验收：手机播放可见，定位源片段后显示对应时间；已有封面待办打开封面轨道，已有质量提醒打开质量面板，工作区滚动仍为 0。浏览器无脚本异常，未出现写入 API 请求。测试没有生成、重试、确认、导出或删除真实任务。

刷新网页即可生效，无需重启后端。
