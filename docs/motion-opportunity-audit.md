# ClipTalk 页面动效机会审计与实施方案

> 审计基线：`d58a0bd`（2026-09-15）
>
> 范围：`static/index.html`、`static/app.js`、`static/app-shell.js`、`static/agent-workspace.js` 及其样式层
>
> 结论：ClipTalk 是高信息密度、长时间使用的专业剪辑工作台，动效应主要解释状态与空间关系，不应装饰时间线或播放操作。

## 1. 页面与现状

当前前端是一个原生 JavaScript 驱动的单页工作台，主要界面可分为五组：

1. 首页与新建任务：任务动态、素材上传、快速工作流入口。
2. 对话与计划：剪辑助理、计划 Dock、计划/活动抽屉。
3. 审核工作区：播放器、时间线、候选镜头、人物/说话人和证据面板。
4. 完成与确认：Toast、动作确认、导出结果、待处理事项。
5. 二次精剪：素材库、播放器、时间线、字幕与属性检查器。

视觉核验表明，页面已经有稳定的深色工作台层级，动效词汇也已有基础：

- `static/cliptalk-tokens.css:54-57` 定义了 `120ms`、`180ms`、`240ms` 和 `cubic-bezier(.2, .75, .25, 1)`。
- 任务抽屉在 `static/app-shell.css:1902-1917` 使用透明度与横向位移建立来源关系。
- 候选抽屉在 `static/styles.css:525-528` 使用从右侧进入的 `220ms` 位移。
- Agent 计划抽屉在 `static/agent-workspace.css:395-409` 已有 `190ms` 透明度过渡，但声明的 `transform` 尚未形成实际位移。
- 按钮和加载状态已有足够的按压反馈、骨架屏与生成中动画，不需要再增加装饰性运动。

因此，本方案延续现有 token，不引入新的缓动体系；所有界面过渡只使用 `transform` 与 `opacity`，不动画布局尺寸、阴影、滤镜或颜色。

### 2.1 字幕校对抽屉

四道筛选：

- **频率**：偶发；只在字幕草稿需要人工校对时进入。
- **目的**：空间一致性、避免突变；右侧工作抽屉应明确从右侧进入并原路离开。
- **速度**：`240ms` 面板、`180ms` 遮罩，均在工作台界面的 300ms 预算内。
- **功能**：运动只解释层级，不移动字幕文本、视频内容或当前编辑数据。

实施要点：

- 保留抽屉节点，使用 `data-state="opening|open|closing"` 或等价 class 管理生命周期。
- 打开时先移除 `hidden`，下一帧进入 `open`；关闭时先设为不可交互并播放退出，收到 `transitionend` 后再添加 `hidden`。
- `aria-hidden` 与 `inert` 应按交互状态更新：关闭开始时立即禁止交互，视觉退出完成后隐藏。
- 快速连续开关必须可重新定向，不排队播放关键帧。

### 2.2 Toast

四道筛选：

- **频率**：偶发；错误或关键动作反馈可能连续出现，但不是逐帧或逐编辑动作触发。
- **目的**：反馈、空间一致性；右下角消息应从其停靠边缘进入和退出。
- **速度**：透明度 `180ms`，位移 `240ms`。
- **功能**：不遮挡主任务、不延迟消息文字呈现，点击关闭仍立即生效于交互层。

实施要点：

- `clearToast()` 不应直接清空容器；先添加退出态，结束后再删除当前 Toast。
- 新 Toast 替换旧 Toast 时，旧项快速退出后挂载新项，或以唯一 token 防止旧回调误删新消息。
- 自动关闭计时仍为现有 `5200ms`，只把 DOM 清理延后最多 `240ms`。

### 2.3 确认与结果弹窗

四道筛选：

- **频率**：动作确认属偶发，导出完成属稀有。
- **目的**：状态指示、避免突变；弹窗代表进入需要集中注意力的新层级。
- **速度**：卡片 `240ms`，遮罩 `180ms`。
- **功能**：居中弹窗不应从触发按钮飞入；轻微缩放只强化模态层级，不暗示错误的空间来源。

实施要点：

- `.action-confirm-card`、`.ct-task-dialog` 共享同一进入配方，避免两个弹窗系统产生不同手感。
- 原生 `<dialog>` 可使用 `@starting-style`；关闭需在动画完成后调用 `close()`，并保留 Esc、焦点恢复和 backdrop 行为。
- 缩放下限为 `.97`，不要从 `scale(0)` 或使用弹跳曲线。

### 2.4 快速工作流选择器

四道筛选：

- **频率**：每个新任务偶发。
- **目的**：状态指示、解释；让用户理解设置面板由输入区的快速剪辑入口展开。
- **速度**：`180ms var(--ct-ease)`。
- **功能**：只动画面板合成层；不动画表单高度，也不逐项延迟可点击时间。

实施要点：

- 先生成内容再进入，避免空容器先闪现。
- 收起结束后再执行当前的 `picker.innerHTML = ""`。
- 不建议给四个模式卡片加 stagger；用户需要立即比较和点击全部选项。

### 2.5 Agent 计划抽屉

四道筛选：

- **频率**：偶发；只在检查计划或活动时打开。
- **目的**：空间一致性；代码已将抽屉锚定到助手面板右侧，位移应表达这层关系。
- **速度**：复用 `180ms` 面板 token。
- **功能**：仅补足已有过渡语义，不移动计划内部的可读内容。

实施要点：

- 将硬编码 `.19s ease` 收敛到 `var(--ct-duration-panel) var(--ct-ease)`。
- 闭合位移为 `-12px` 而不是整屏滑入，避免覆盖播放器时产生沉重感。
- 现有 `190ms` 延迟隐藏逻辑应同步为 token 对应值，或改为监听 `transitionend` 加超时兜底。

## 3. 明确不建议的候选

- `static/app.js:16339-16346` 及播放器/时间线播放头：**频率淘汰**。播放、逐帧、跳转和键盘操作一天可能发生上百次，任何补间都会让时间定位显得不准确。
- `static/app.js:23633-23651` 的精剪快捷键，以及 `static/secondary-editor-focus.css:77-89,382-393` 的素材库/检查器：**频率与功能淘汰**。这些是高频、信息密集的编辑操作；打开侧栏应即时响应，不做滑入或 stagger。
- `static/styles.css:525-528` 的候选抽屉：**已有正确实现**。它已经从右侧以 `220ms` 位移进入，空间故事完整；只可在未来维护时换成共享 token，不应叠加新效果。
- `static/app-shell.css:1902-1917` 的任务列表抽屉：**已有正确实现**。透明度与位移均已覆盖，继续增加缩放或列表逐项进入会拖慢任务切换。
- `static/app-shell.js:404-435` 的首页、成片库、设置和工作区切换：**功能淘汰**。这些是顶层导航；全页转场会延迟页面辨识并可能制造大面积闪烁。保留即时切换更符合专业工具。

## 4. 无障碍与降级策略

新增动效必须覆盖 `prefers-reduced-motion: reduce`，但无需把所有状态桥接完全关闭：

- 面板和 Toast 的移动距离降为 `4px`，弹窗缩放起点改为 `.99`。
- 所有新增过渡统一缩短为 `var(--ct-duration-hover)`（`120ms`）。
- 持续循环、闪烁和 stagger 一律不新增。
- 焦点移动、`aria-hidden`、`inert` 和键盘关闭逻辑不依赖动画完成；`transitionend` 只负责最终 DOM 隐藏/删除。
- 不支持 `@starting-style` 的浏览器应直接显示最终状态，功能不能依赖进入动画。

## 5. 推荐实施顺序

1. 先抽出轻量的进入/退出状态约定，并覆盖快速重复触发测试。
2. 实现字幕校对抽屉和 Toast；这两项收益最大，也能验证抽屉与临时消息两类生命周期。
3. 统一确认/结果弹窗。
4. 接入快速工作流选择器和 Agent 计划抽屉。
5. 最后统一检查 reduced-motion、键盘焦点、Esc、遮罩点击和窄屏表现。

建议分成两个实现 PR：第一组包含字幕抽屉、Toast 与通用生命周期；第二组包含弹窗、快速工作流和计划抽屉。这样可以分别回归高风险的 DOM 清理与低风险的 CSS 补足。

## 6. 验收清单

- 所有进入和退出都在 300ms 内完成，且不阻塞首次点击。
- Chrome Performance 面板中只触发合成层属性，不因动效产生持续 Layout/Paint。
- 连续快速打开、关闭、再次打开时，最终可见性、焦点和 `aria-hidden` 一致。
- Toast 被新消息替换时，旧计时器不会删除新消息。
- 字幕校对、确认弹窗关闭后焦点回到原触发控件。
- `prefers-reduced-motion: reduce` 下仍能理解状态变化，且位移不超过 `4px`。
- 任务抽屉、候选抽屉、时间线、播放器与精剪快捷键行为保持不变。

## 7. 总体判断

ClipTalk 当前并不缺少“氛围动效”，缺少的是少数覆盖层的状态桥接。最值得优先实现的是字幕校对抽屉：它占据大面积视野、方向明确且出现频率适中，短促的右侧进入/退出能显著降低界面跳变。其余区域应继续保持克制，尤其不要让时间线、播放器和高频精剪操作产生惯性或等待感。
