# ClipTalk 动效与进度显示改进（2026-09-25）

保留原有森林绿主题、字体和左右分栏。参考 Beautiful UI 的紧凑任务层级与 Generative Loaders 的局部等待效果；改动仅涉及前端展示、上传传输反馈和浏览器测试。

## 已实现

- Agent 执行卡使用 20px Aperture 表达不确定等待；没有可靠进度时隐藏扫描条。有真实进度时冻结图标，更新实际计数与细进度条。进度更新同时校验任务、计划和步骤，避免跨步骤沿用百分比。
- 封面生成阶段以图片占位作为唯一持续运动焦点，保留目标宽高比；普通缩略图改为静态 Skeleton。图片解码成功后显现，封面失败显示静态错误，图片资源的临时 URL 在失败时也会释放。
- 规划阶段取消重复扫描动效，保留当前阶段与耗时。对话中的耗时定点更新，避免只因计时变化重建 Loader。步骤详情使用编号、完成勾选、跳过及失败符号。
- 小文件上传使用 XHR 的真实传输回调，大文件继续复用可续传上传器。传输完成但任务尚未创建时显示“上传完成，正在准备预览”；不把传输 100% 当作预览已经可用。
- 保留 Cascade 的轻量显现风格，由适配层按 Unicode 字素呈现新增文字；已有字符节点不重建，中文及混合文本正常换行，表情不拆分。可访问内容使用实际文字，不在每个增量上重复播报整个回答。
- 新的结果卡和候选结果使用一次性 240ms、4px 显现；历史恢复、重复轮询及减少动态效果模式不重播。用户向上阅读时保留滚动位置。
- Generative Loaders 与 Thinking Orbs 共用生命周期管理：隐藏、离屏、后台、停止及减少动态效果时暂停；移除节点时清理挂载。参数不变时跳过重复渲染。动态球体随页面主题变化，紧凑位置统一使用受支持的 20px 预设。
- 执行卡按钮明确使用主题色、键盘焦点和稳定最小宽度；计划操作按钮沿用 120ms 反馈，详情抽屉使用 180ms 过渡。

## 接口及维护

后端接口与数据格式不变。前端 `ClipTalkApi.request` 的 options 新增可选 `onUploadProgress(fraction)` 回调；只有提供该回调的请求使用 XHR，继续复用原有会话请求头、认证重试与结构化错误处理。

生命周期逻辑位于 `frontend/loader-lifecycle.js`，由既有两个 bundle 打包，不增加生产脚本或样式表。修改适配层后执行 `npm run build:loaders`、`npm run build:orbs`。工作台新增样式归入原有 `workbench.css`，静态资源版本已更新。
