# 内容检索与合成可靠性改进

## 修复的通用问题

原实现可能将单帧命中推断成整段成立，并把匹配分数当作边界置信度。后续合成除了沿用宽范围，还存在为满足时长而扩展候选、候选创建失败后退回高光或全片的路径。

新增 `app/content_contract.py`，把候选范围、证据范围、允许使用范围、原始条件和核验状态分开。新检索缓存版本为 `content-search-v41-evidence-edit-contract-20260910`；旧任务和媒体不迁移、不批量重算。

## 已接入的行为

- 物体、屏幕文字等视觉出现条件逐采样点核验；消失、不确定或缺失的点切断连续范围，边界附近进一步加密。不再给单帧自动加前后各一秒的已确认片段。
- 动作事件、对白与主题内容走整段语义策略，而不是强制要求每帧都出现目标。对白提供真实转写及词级边界；有明确身份绑定的人物出镜复用人物轨迹。
- `all`、`any`、`not` 使用三值逻辑；未知不能当作“不存在”。排除条件和时间关系必须得到明确支持。
- 无法自动核验的候选保留供审核，不能自动成为可剪范围。识别可信度与边界可信度不再相互回填。
- 后续“合起来／改竖屏”保留条件和选择快照。时间线绑定检索、匹配范围与版本指纹；跨检索清单分别保留每段的原始条件。
- 历史所选结果按需核验；改变范围时创建新检索修订并暂停检查，保留旧结果、旧预览和手动草稿。人工保存边界或逐项确认保留记录为 `human_confirmed`，不伪装成模型核验。
- 自动合成不得退回无关高光或全片；时长目标不得扩大候选范围。完整表达被截短、选择顺序改变、插入未知来源或补画面都会触发检查。
- 自动应用提案前在副本上核验整个批次，避免应用一半后才发现不合规。人工内容审核完成后重试原提案步骤，不跳过尚未创建的时间线。
- Agent 审核样片检查实际输出画面；内容检查独立于媒体技术质检。抽检失败或不可用保留预览并显示待复核，不声称全部通过。
- 直接合成与跨检索清单新增 `acknowledgeUnverified`（默认 false）。它独立于接受可能遗漏的确认，且记录本次接受的范围；精剪导出复用警告确认机制。
- 输出片段保存原始条件和核验记录，供再次精剪和交付检查使用。接受未核验内容后生成的版本标为待复核。

## 核验边界与成本

当前是有预算的证据核验，不是识别准确率保证，也不宣称找全或逐帧验证。视觉初始采样间隔 0.25 秒，状态交界加密至约 0.083 秒；事件和语义区间按完整上下文检查。默认每次候选核验最多 480 个采样点、48 次模型调用，预算不足保留待审核结果。成片抽检最多 24 个片段，每段 5 帧。

没有可靠身份关联、主动说话人或声音事件证据时转人工审核，不用静态画面猜测声音或身份。成片对白沿用源转写与范围校验，不把它称为重新识别成片音轨。上述限制通过状态和报告呈现。

## 验证与部署

回归覆盖单帧误扩展、无关尾部、目标间断、未知与否定、复合条件、语义完整性、预算耗尽、模型失败、旧结果重核验、选择快照、清单来源、人工确认、实际输出抽检以及普通高光不受影响。

测试使用隔离夹具和模拟识别响应，不覆盖已有用户视频或成片。代码生效需要在没有执行中任务时重启后端并刷新前端；本次不自动重启服务，也不自动重新生成用户历史任务。
