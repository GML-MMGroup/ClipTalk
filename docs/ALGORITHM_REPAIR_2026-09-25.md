# 算法流程修复与验收

范围：要求解析、组合能力、检索证据、片段选择、要求覆盖、版本继承、
时长与时间映射、字幕检查、执行与恢复。保留现有工作区修改和用户任务数据。

## 顺序

1. 回归已确认问题：否定/转折、小数时长、声音能力、组合动效、反面证据、质检漏项。
2. 统一正文与片头预算，保护正式成片的版本继承和定位时间。
3. 消除候选数量断崖，按预算抽检而不是超过数量就全部放弃。
4. 完善取消、修复路由及重复处理控制。
5. 运行离线回归和本地合成媒体测试；真实模型质量评测单独记录，不以模拟测试替代。

## 验收原则

- 未执行或未检查的要求不得标成完成。
- 不支持人声分离等能力时明确阻止，不用降噪冒充。
- 修改只影响指定部分，不静默退回旧时间线。
- 抽样不代表逐帧检查；预算不足要保留未检查范围。
- 取消及过期任务不得发布结果。
- 不为了并行而打破已有任务锁和修改顺序。

## 已实现

| 原问题 | 本次处理 | 验证方式 |
| --- | --- | --- |
| 否定和转折混在一起 | 保留转折后的肯定要求；音频否定单独生效 | 同义句回归 |
| 小数时长和误差丢失 | 保留小数，支持文字形式的误差和零误差 | 15.5 秒、±0.5 秒、误差 0 秒 |
| 组合动效漏执行 | 自动交付可附加动态片头；不支持的动效或审核组合明确阻止 | 计划/效果配置与真实动效测试 |
| 音频优化不分需求 | 音量、静音、响度、降噪分开；音乐分离不再冒充完成 | 真实音频降低 6 dB 的测量 |
| 关键词盖过反面证据 | 明确否定的候选不能由关键词重新提升为可靠 | 包括否定分数为 0 的回归 |
| 17 个候选出现断崖 | 超过 16 个使用有预算的组合搜索；必选片段不静默删除 | 16/17/50/200 个候选及必选冲突 |
| 质检清单由模型自行缩减 | 检查前生成来源于原查询的清单及稳定编号，缺项标记未检查 | 多条件、14 项要求、专有词中的“和” |
| 正文和片头预算不同步 | 编排使用正文预算，自动交付检查使用最终时长 | 15 秒含 1 秒片头，正文 14 秒 |
| 换封面回到祖先时间线 | 优先选定正式版本，移除已记录的旧封面区间再合成 | 真实视频替换片头，时长不累加 |
| 抽检时间与成片偏移 | 保存交付时间线及正文偏移，质检和前端时间轴共同读取 | 多片头及历史时间线被修改后的定位 |
| 数量超限直接不检查 | 字幕按 48 帧预算分配；成片抽检覆盖最多 24 段并记录遗漏范围 | 9 段可检查、49 段不虚报全覆盖 |
| 多次渲染与粗粒度重试 | 简单自动任务先核对时间线后直接正式渲染；修复只失效依赖节点 | 预检查不创建样片、指纹变化拒绝交付 |
| 停止不及时 | 声音/片头/动效使用可取消进程，过期回调也终止进程 | 真实子进程取消及过期任务回归 |
| 封面只看元数据 | 最终开头抽帧与确认封面做图片比较，不能检查时保留未知 | 新封面通过、旧封面不匹配 |

自动修复限制：同一修复工具与问题码组合最多重试一次；不同原因合计最多三次。
历史文件不覆盖。没有修改现有任务的数据，也没有重启线上进程。

## 第二批：字幕证据复用与衍生版本继承

本批实施顺序：先补逐帧缓存及失效测试，再接入已有处理路径的版本继承，最后检查取消/版本变化时是否会误写结果。

- 字幕检查新增跨任务逐帧缓存。只有素材身份、抽样时间、实际图片内容、已解析的模型及服务地址、思考/返回格式配置和检查规则一致才复用。更换任一项就重查；模型身份不完整时不启用缓存。
- 缓存只保存确定的单帧结果，不缓存“无法判断”，更不能把单帧结论变成整片无字幕。最多 8192 条、保留 7 天，存储不可用时退回正常检查；数据库不保存密钥、服务地址或模型响应原文。
- 检查报告区分实际检查片段、计划检查片段、模型调用数及缓存命中数。提前发现字幕或不确定性而停止时，不再显示已经检查完全部范围。
- 动态片头、画幅预览、音频处理、正式文件复制四条已有路径接入统一的版本继承。保留冻结时间线、字幕和先前处理记录；新增片头同步移动正文偏移、已有封面位置和字幕时间。这里仅适用于正文时间不变的处理，不包含变速、重排和裁剪。
- 由审核样片合成的动态片头版本继续标记为审核样片，不再冒充正式导出。改变画面或声音后，原“质检通过”状态重置为待检查。
- 字幕检查过程中若任务取消或时间线版本改变，拒绝把旧结果应用到新时间线。手动动态片头合成也接入可取消进程。
- 手动音频工具的默认行为与明确操作对齐：单独调音量、静音或降噪不再偷偷附加响度标准化；明确要求标准化时仍可组合执行。
- 新增离线测试覆盖跨任务复用、配置失效、缓存损坏/过期/并发/容量、抽检不完整、取消、时间线变化、连续处理的时间映射，以及实际工具调度中的样片身份与版本继承。

本批没有改界面、启动或停止服务，也没有对用户素材调用真实模型。

## 第三批：旧封面入口与导出一致性

排查发现：旧封面入口仍通过返回源视频/祖先版本来避免片头重复，可能丢失后来调整的声音、画幅等；直接操作已有片头文件时又可能重复叠加。正式导出入口则只复制文件，目标画幅此前仅写入标签。

本批按“统一时间映射 → 接入旧入口 → 校验导出 → 合成媒体回归”的顺序处理：

- 两个旧封面处理入口改为从选定版本中移除有记录的旧封面区间，再添加新封面。已存在的动效片头、声音处理和正文保留，不再退回祖先版本。
- 只允许替换明确位于正文之前的封面区间；时间记录缺失或越界时拒绝猜测裁切。中间文件独立命名并清理，原视频不覆盖。
- 新版本记录正文偏移、封面起点、字幕时间和替换操作。自动交付也同步修复了添加/替换片头后导出字幕时间未移动的问题；更改媒体后清除旧的质检通过状态。
- 时间轴提交封面时不再预先重绑历史版本的封面文件，只在新版本成功后绑定新封面。
- 合成过程中取消、改选封面或切换当前成片时，不发布过期结果。旧手动任务失败回调不再把这些新选择写回旧的失败状态。
- 正式文件复制导出也在提交前再次检查取消与版本变化。封面成片已发布后，即使发送完成通知失败，也不再删除已经被新版本引用的视频。
- 正式文件复制导出前探测真实视频尺寸：画幅不符或参数不支持时停止，不以改标签冒充画幅转换。本批没有新增裁切或重构能力，仍需先完成画幅调整。
- 真实合成视频验证了“旧封面前已有另一段片头”的替换场景：逐段检查新封面、保留片头、正文的画面顺序、音轨、时长和字幕时间，并验证旧视频和旧封面文件未改变。

## 完整计划中仍未完成的部分

以下不属于“单元测试通过就已实现”，不能报告为全部完成：

1. 所有意图解析器统一为一个完整语义要求模型。目前统一的是交付时长、音频操作和质检要求清单，原有多入口解析仍在。
2. 完整操作图及任意组合能力。当前保障自动模式的已支持组合；审核模式不支持的声音/动效组合会明确阻止。人物访谈、多画幅多版本、动态字幕等还需要专项联调。
3. 所有导出路径统一继承操作记录。目前覆盖新自动交付、四条衍生处理路径及两个旧封面合成入口；历史文件不会被批量迁移，其他导出路径仍需继续核对。
4. 长视频分层召回调优、分析步骤的资源受限并行。字幕检查已增加跨任务逐帧缓存，但并非所有分析证据都已统一复用；没有为了提高并行度绕过现有状态锁。
5. 最终字幕与标题的 OCR 可读性、最终音频的语义复核。封面图片相似性检查不是文字可读性验收。
6. 有人工真值的真实模型评测。仓库有评测器和标注说明，但缺少 `benchmarks/algorithm-v2-evaluation.jsonl` 等正式评测输入，不能填入虚构准确率或用合成媒体代替长视频质量结论。
